## 1. 接线与上电（LD2451）

- [x] 供电 **5V，电流 > 200mA**；串口 TTL；当前真机为 **256000 / 8 / N / 1**。
- [ ] 接线：VIN→5V、GND→GND、雷达 TX→主控 RX、雷达 RX→主控 TX（**TX/RX 交叉**）。
- [x] Linux主机串口已确认：雷达/dev/ttyUSB1，GPS/dev/ttyUSB0。
- [x] DK2500串口路径已验证：雷达/dev/ttyUSB1，GPS/dev/ttyUSB0（注意：两个CH340共享相同序列号，需通过USB物理路径区分）。
- [ ] 注意 IO 电平 **3.3V**，与主控电平匹配（必要时电平转换）。

## 2. 安装方向（前装，关键）

- [ ] 雷达装在**车前侧、朝正前方**。
- [ ] **±15° 宽探测轴必须水平（左右）**——不要装成竖向（否则成上下扫，看不到左右目标）。
- [ ] 天线正面无遮挡；背面尽量无运动物（雷达有背瓣穿透，必要时加金属背板屏蔽）。
- [ ] 雷达与摄像头**尽量同位、同朝向、刚性固定**（减小视差与晃动）。

## 3. 雷达参数配置（用海凌科手机 APP 或串口命令）

- [ ] 检测方向：设 **「均检测」(02)** 或 **「靠近」(01)**（前向避障靠近最关键）。
- [ ] 最远检测距离：按需（默认 100m；电动车近场为主可调小）。
- [ ] 最小检测速度：调低（利于捕捉近距未知障碍）。
- [ ] 灵敏度：触发次数 1~2、信噪比阈值默认 4（除非误报多再调）。
- 配置命令流程见 `LD2451 串口通信协议` §1.4（使能配置 → 下发 → 结束配置）。

## 4. ★ 标定项（融合精度依赖，逐项确认并回填配置）

| 标定项 | 怎么测 | 回填到哪 |
|---|---|---|
| **相机水平 FOV** | 查摄像头规格 或 棋盘格标定 | `VisionRadarFusionConfig.camera_fov_h_deg` |
| **雷达角度左右符号** | 在画面**右侧**放一个目标，看雷达上报角度是 **+ 还是 −** | 若与相机右侧相反 → `flip_radar_angle=True` |
| **速度方向 00/01**（安全关键） | 已用左前靠近目标真机标定 | `01=靠近`，接近速度为负 |
| 雷达-相机时间对齐 | 同一动作下看两者时间戳偏差 | 同步策略（取最近一帧雷达配当前画面） |

> 速度方向那条**最致命**：手册表9与示例自相矛盾，取反会把"接近"当"远离"→ TTC 失效 → **漏报**。务必实测确认。

## 6. 功能验证（各机制是否生效，先定性过一遍）

- [ ] 回放真实雷达 + 对应视频，跑融合，逐帧看：

- [ ] 端到端 `main_integrated.py --mode real --vision true`，看风险等级与马达响应是否合理。

## 7. 视觉风险效果测试与评估（重点：判断"风险算得准不准"）

> 目标：用**受控场景 + 量化指标**实测视觉风险链路效果，而不是只看"感觉合理"。
> 数据来源：CSV 日志已记录 `timestamp / risk_obs / risk_total / risk_level / radar_nearest_m /
> radar_min_ttc / vision_max_risk`，可直接画**风险-时间曲线**；离线用 `replay_radar.py` 反复复现。

### 7.1 场景化测试矩阵（摆拍/受控，对照预期）

| 场景 | 预期表现 | 重点看 |
|---|---|---|
| 正前方车辆**由远及近** | 风险随距离↓、TTC↓ **平滑上升**，到临界触发中→高风险+马达 | 风险曲线是否单调、**警报提前量** |
| 两轮车**横穿/切入**前方 | 检出+在途 → 中/高风险 | 是否**及时**（提前量） |
| 路边**静止护栏/停车**（骑行经过） | 风险≈0（角度+路面门控滤掉） | **不误报**（不误震） |
| **视觉漏检但雷达看到**（夜间/弱光/小目标） | 仍输出"未知障碍"风险，日志出现 `雷达兜底未知障碍` | **雷达兜底是否生效** |
| 空旷直道、无障碍 | 风险低、无警报 | **不误震**（可用性） |
| 行人/车在**画面边缘（>15°）** | 视觉报、雷达看不到 → 仅视觉风险 | 不因雷达没看到就漏 |

### 7.2 量化指标（每场景采集，给出数字而非"感觉"）

- **警报提前量**：从"系统给出中/高风险"到"实际到达危险点（TTC≈临界）"的时间，越大越好。
- **漏报率**：受控威胁场景里，**未被及时报警**的比例（尤其两轮车、夜间）——安全命门，应≈0。
- **误报率**：安全骑行（无真威胁）下的**误警报次数/分钟**——太高骑手会弃用。
- **雷达补漏次数**：视觉漏检、靠雷达救回的目标计数（体现融合价值）。
- **等级稳定性**：风险等级是否频繁抖动（1↔2 跳变）；抖动多说明要加平滑/迟滞。

### 7.3 消融对比（证明"加雷达确实有用"，写报告很有说服力）

- [ ] 同一段录制，跑**两遍**：① 正常融合；② 把雷达置为无效（`RadarData.valid=False`，或回放空雷达）。
- [ ] 对比两者的**风险曲线 / 漏报 / 提前量**——量化雷达带来的提升（尤其夜间/小目标场景）。
- 也可对比 `vision_max_risk`（纯视觉）vs `risk_obs`（融合后）两列，直接看雷达把风险估准了多少。

### 7.4 验收建议（达标线，可按实测调整）

- 正前方逼近威胁：在 **TTC ≈ 临界（2~3s）前**给出中/高风险，**提前量 ≥ 1~2s**；
- 已知威胁**漏报率 ≈ 0**（两轮车、夜间重点）；
- 安全骑行**误报 < 1 次/分钟**；
- 风险等级**不频繁抖动**（必要时加迟滞/多帧确认）。

## 8. 端侧延迟与参数标定（DK-2500 上）

### 8.1 端侧延迟（实时地板线）

- [ ] 量整环延迟（检测+分割+融合+风险），确认 **≥10FPS（≤100ms）**。
- [ ] 量化模型（FP16/INT8）上板量延迟（模型本身的产出/精度属视觉模型测试，非本清单）。

### 8.2 ★ 核心参数标定（当前全是经验默认值，必须用真实骑行数据定）

> ⚠️ 关键前提：权重/阈值**不能凭空"测"**，得先定义"什么算真正的危险"（标签来源），否则无从拟合。
> 三种标签来源按成本：① 脚本化场景预期排序（最省，比赛首选）；② 雷达 TTC 当监督信号（数据驱动）；③ 人工标注危险度（最贵，可不做）。

**A. `TTC_safe` 标定（分布法）** — 当前 5s（按"反应 1.5s + 顶速 25km/h 下 3m/s² 刹停 2.3s + 余量"估的，需实测确认）

- [ ] 录同步数据：前向视频 + 雷达（已记 `radar_min_ttc`）+ IMU（已记 `brake_score`）。
- [ ] 标"真实险情"：用 IMU 急刹/急转尖峰 + 回看视频，标出骑手**不得不避让**的时刻。
- [ ] 记每个险情里**骑手开始反应那一刻的 TTC**（t_react），统计其分布。
- [ ] **`TTC_safe` 取该分布的偏上分位（75%~90%）**，保证报警在骑手自己反应之前发出。
- [ ] 回放验证：正常段误报率 + 险情段提前量（目标 ≥1~2s，见 §7.4），微调定值。
- 回填：`configs/risk_params.yaml` 与 `VisionRadarFusionConfig` 的 `ttc_safe_sec`。

**B. 视觉风险 4 权重标定**（`w_proximity/lateral/drivable/size` = 0.30/0.25/0.12/0.08）— 按精力选档

- [ ] **档1 场景调参（比赛够用，先做）**：用 §7.1 场景矩阵（每个场景有预期风险等级），跑后看实际
      逐目标 risk / risk_level 是否符合预期；不符就定位是哪个因子主导错了、手调对应权重；
      **做消融**（逐因子置 0 看行为变化）确认每个因子有用且方向对。
- [ ] **档2 雷达 TTC 监督回归（数据驱动升级）**：在**视觉∩雷达都看到**的目标子集上，4 个视觉因子是
      特征、雷达运动学风险 `k_kin`（真实 TTC/距离）是目标真值，做**带非负约束的线性回归**拟合权重，
      再用到纯视觉目标。预期纵向接近度因子自然拿到大权重（印证 0.30）。
- [ ] **档3 人工标注（可选，最贵）**：多人对抽样目标打 0-1 危险度或成对比较，learning-to-rank 拟合。
- 回填：`VisualRiskConfig` 的 `w_proximity / w_lateral / w_drivable / w_size`。

**数据采集要求**

- [ ] 现有 CSV 已记 `risk_obs / radar_nearest_m / radar_min_ttc / vision_max_risk`；
- [ ] **需补记**（在 fusion 里加几行临时日志）：逐目标的 4 因子值 + 该目标是否匹配上雷达；
- [ ] 同步录视频供事后标注；场景覆盖：白天/夜间、空旷/拥挤、有/无两轮车、正前逼近/横穿/路边静止。

> 💡 提醒队友：**权重绝对值不如"比例 + 最终风险等级阈值/迟滞"重要**。真正目标是端到端"该报就报、
> 不该报不报"——所以即使只做档1 + 提前量/误报率两个指标，也能定出一套可辩护的参数。

### 8.4 分割形态学后处理验证（本次新加代码，需在真实掩码上确认）

> `postprocess.py` 的 `refine_drivable_mask`：默认对 road 掩码做开运算去飞点 + 闭运算填小洞（~0.6ms），
> 让雷达路面门控更稳。需在真实/录制掩码上确认参数没副作用。

- [ ] 真实路面掩码上确认：默认 `morph_kernel=5` 的 open+close **没削掉远处细窄真路面**、
      也**没把路面上真实障碍处的空洞填掉**（大洞不该填）。削太多→减小核或关 `do_open`；飞点没去净→增大核。
- [ ] 决定是否开 `keep_largest`（默认关）：场景有合法分叉可行驶区（岔路口）→保持关；
      只关心正前主路面、远处碎块干扰门控→可开。回填：`build_segmentation_result_from_label_map` 调用处。

### 8.5 （二期/展望）环境收窄风险 R_env

- [ ] 当前 `drivable_area_ratio`（整画面路面占比）只做显示，**未进风险**。可作二期改进项：施工/违停占道→
