# 硬件实测清单（视觉-雷达融合）

> 给上车实测的同学：所有**必须有硬件才能做**的事，按顺序列在这。软件侧（融合模块、录制/回放、
> 端到端 mock）已就绪，硬件一到照此清单走即可。配套设计见 [`视觉雷达融合设计.md`](视觉雷达融合设计.md)。

---

> 模型选型/FP16/INT8 属**视觉模型测试**（见 `精度评测结果.md` 的"部署模型"），不在本清单。

## 1. 接线与上电（LD2451）

- [ ] 供电 **5V，电流 > 200mA**；串口 TTL，**115200 / 8 / N / 1**。
- [ ] 接线：VIN→5V、GND→GND、雷达 TX→主控 RX、雷达 RX→主控 TX（**TX/RX 交叉**）。
- [ ] 确认串口号，填到 `configs/sensor_ports.yaml` 的 `radar.port`（Win 形如 COM7，Linux 形如 /dev/ttyUSB0）。
- [ ] 注意 IO 电平 **3.3V**，与主控电平匹配（必要时电平转换）。

## 2. 安装方向（前装，关键）

- [ ] 雷达装在**车前侧、朝正前方**。
- [ ] **±15° 宽探测轴必须水平（左右）**——不要装成竖向（否则成上下扫，看不到左右目标）。
- [ ] 天线正面无遮挡；背面尽量无运动物（雷达有背瓣穿透，必要时加金属背板屏蔽）。
- [ ] 雷达与摄像头**尽量同位、同朝向、刚性固定**（减小视差与晃动）。

## 3. 雷达参数配置（用海凌科手机 APP 或串口命令）

- [ ] 检测方向：设 **「均检测」(02)** 或 **「靠近」(01)**（前向避障靠近最关键）。
- [ ] 最远检测距离：按需（默认 100m；电动车近场为主可调小）。
- [ ] 最小检测速度：调低（利于捕捉近距未知障碍）。
- [ ] 灵敏度：触发次数 1~2、信噪比阈值默认 4（除非误报多再调）。
- 配置命令流程见 `LD2451 串口通信协议` §1.4（使能配置 → 下发 → 结束配置）。

## 4. ★ 标定项（融合精度依赖，逐项确认并回填配置）

| 标定项 | 怎么测 | 回填到哪 |
|---|---|---|
| **相机水平 FOV** | 查摄像头规格 或 棋盘格标定 | `VisionRadarFusionConfig.camera_fov_h_deg` |
| **雷达角度左右符号** | 在画面**右侧**放一个目标，看雷达上报角度是 **+ 还是 −** | 若与相机右侧相反 → `flip_radar_angle=True` |
| **速度方向 00/01**（安全关键） | 用一个**已知正在逼近**的目标，确认 `radar_reader` 解出的相对速度是**负**（接近） | 若反了 → 改 `radar_reader.py` 的 speed_dir 判断 |
| 雷达-相机时间对齐 | 同一动作下看两者时间戳偏差 | 同步策略（取最近一帧雷达配当前画面） |

> 速度方向那条**最致命**：手册表9与示例自相矛盾，取反会把"接近"当"远离"→ TTC 失效 → **漏报**。务必实测确认。

## 5. 录制真实数据（打通离线调试）

- [ ] 用 `scripts/record_radar.py`（软件已就绪）连雷达，录一段到 `logs/radar_*.jsonl`。
- [ ] 同时录一段对应的**摄像头视频**（时间对齐，便于联合验证）。
- [ ] 覆盖几类场景：正前方逼近车辆、侧前方两轮车、路边静止护栏（验证门控）、夜间/雨天若可。
- [ ] 录完用 `scripts/replay_radar.py` 回放喂融合，离线反复调参，无需一直占用硬件。

## 6. 功能验证（各机制是否生效，先定性过一遍）

- [ ] 回放真实雷达 + 对应视频，跑融合，逐帧看：
  - 视觉∩雷达目标的 **距离/TTC 合理**（与肉眼/卷尺大致对得上）；
  - 仅雷达未知障碍 **只在路面+在途时保留**（路边护栏应被门控丢弃）；
  - 左右目标关联 **没镜像**（验证 §4 角度符号）；
  - 持续性：单帧闪烁不报、稳定目标风险逐帧上升。
- [ ] 端到端 `main_integrated.py --mode real --vision true`，看风险等级与马达响应是否合理。

## 7. 视觉风险效果测试与评估（重点：判断"风险算得准不准"）

> 目标：用**受控场景 + 量化指标**实测视觉风险链路效果，而不是只看"感觉合理"。
> 数据来源：CSV 日志已记录 `timestamp / risk_obs / risk_total / risk_level / radar_nearest_m /
> radar_min_ttc / vision_max_risk`，可直接画**风险-时间曲线**；离线用 `replay_radar.py` 反复复现。

### 7.1 场景化测试矩阵（摆拍/受控，对照预期）

| 场景 | 预期表现 | 重点看 |
|---|---|---|
| 正前方车辆**由远及近** | 风险随距离↓、TTC↓ **平滑上升**，到临界触发中→高风险+马达 | 风险曲线是否单调、**警报提前量** |
| 两轮车**横穿/切入**前方 | 检出+在途 → 中/高风险 | 是否**及时**（提前量） |
| 路边**静止护栏/停车**（骑行经过） | 风险≈0（角度+路面门控滤掉） | **不误报**（不误震） |
| **视觉漏检但雷达看到**（夜间/弱光/小目标） | 仍输出"未知障碍"风险，日志出现 `雷达兜底未知障碍` | **雷达兜底是否生效** |
| 空旷直道、无障碍 | 风险低、无警报 | **不误震**（可用性） |
| 行人/车在**画面边缘（>15°）** | 视觉报、雷达看不到 → 仅视觉风险 | 不因雷达没看到就漏 |

### 7.2 量化指标（每场景采集，给出数字而非"感觉"）

- **警报提前量**：从"系统给出中/高风险"到"实际到达危险点（TTC≈临界）"的时间，越大越好。
- **漏报率**：受控威胁场景里，**未被及时报警**的比例（尤其两轮车、夜间）——安全命门，应≈0。
- **误报率**：安全骑行（无真威胁）下的**误警报次数/分钟**——太高骑手会弃用。
- **雷达补漏次数**：视觉漏检、靠雷达救回的目标计数（体现融合价值）。
- **等级稳定性**：风险等级是否频繁抖动（1↔2 跳变）；抖动多说明要加平滑/迟滞。

### 7.3 消融对比（证明"加雷达确实有用"，写报告很有说服力）

- [ ] 同一段录制，跑**两遍**：① 正常融合；② 把雷达置为无效（`RadarData.valid=False`，或回放空雷达）。
- [ ] 对比两者的**风险曲线 / 漏报 / 提前量**——量化雷达带来的提升（尤其夜间/小目标场景）。
- 也可对比 `vision_max_risk`（纯视觉）vs `risk_obs`（融合后）两列，直接看雷达把风险估准了多少。

### 7.4 验收建议（达标线，可按实测调整）

- 正前方逼近威胁：在 **TTC ≈ 临界（2~3s）前**给出中/高风险，**提前量 ≥ 1~2s**；
- 已知威胁**漏报率 ≈ 0**（两轮车、夜间重点）；
- 安全骑行**误报 < 1 次/分钟**；
- 风险等级**不频繁抖动**（必要时加迟滞/多帧确认）。

## 8. 端侧延迟与参数标定（DK-2500 上）

- [ ] 量整环延迟（检测+分割+融合+风险），确认 **≥10FPS（≤100ms）** 实时地板线。
- [ ] 用真实骑行数据标定风险权重/阈值（`configs/risk_params.yaml` 与 `VisionRadarFusionConfig`）。
- [ ] 量化模型（FP16/INT8）上板量延迟（模型本身的产出/精度属视觉模型测试，非本清单）。

## 9. 设计决策

- ✅ **视觉失效时雷达兜底（已实现）**：R_dist 权重=0（雷达只经融合进 R_obs），但融合在视觉失效/未启用时
      以**纯雷达**运行，摄像头/模型挂掉雷达仍报警。实测建议专门验一项：**骑行中强制关闭视觉**，
      确认雷达仍能对正前方逼近目标触发警报。
- [ ] speed_dir（§4）与角度符号（§4）确认结果，回填配置。
