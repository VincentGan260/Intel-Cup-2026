# RiderGuardian 风险规则模型完整设计（评审修订版）

## 1. 结论与边界

本模型不使用未经标定的模态权重、固定距离区间或神经网络事故概率。风险判断采用“雷达快速安全通道 + 异步视觉辅助通道 + 非对称迟滞状态机”。

上一版存在以下问题，本版已纠正：

- `TTC <= 2.5 s + 系统延迟`只能说明连反应时间都已不足，属于“已经来不及线”，不能作为有效预警线。
- 2.5 s不是头盔振动反应时间实测值，不能直接用于证明振动预警有效性。
- 任何走廊内接近目标都触发中风险容易造成报警疲劳。
- 0.36 m只是最小车体点目标走廊，没有覆盖障碍物宽度、摆动、角度误差和安全余量。
- 雷达向左偏时，安装坐标必须按“左负右正”加入目标横向坐标，不能减错符号。
- 雷达紧急判定必须先于视觉推理，不能等待135 ms视觉链路完成。
- 目标必须通过置信度、距离、方位角、状态和新鲜度检查。
- 风险升级立即发生，风险降级必须采用不增加升级延迟的非对称迟滞。

在没有可靠车速、制动能力和振动反应实验时，系统可以实现完整流程，但不能声称已经获得完整安全停车阈值。需要实测的参数必须保留其来源和状态，不能填写任意常数。

## 2. 系统条件

- 雷达：HLK-LD2451。
- 检测：YOLO26n_v2 INT8，NPU约21 ms。
- 分割：road-segmentation-adas FP16，GPU约114 ms。
- 当前视觉推理约135 ms/帧；正式性能使用DK-2500实测P95。
- 车体与骑行者静态最大宽度：0.66 m。
- 雷达横向误差：0.025 m。
- 雷达位于车体中心左侧约0.055 m。
- 安装位置测量不确定度约0.005 m。
- 当前没有可靠实时车速。
- 当前没有自行车制动减速度实测。
- 当前没有针对实际振动位置、实际骑行者的反应时间实测。
- 当前没有雷达—相机外参，不能声称目标级精确融合。

## 3. 证据来源及适用范围

### 3.1 2.5秒的真实来源

TxDOT自行车设施设计资料在引用AASHTO自行车设计方法时指出，自行车停车视距取决于感知—制动反应时间、初速度、轮胎与路面摩擦、制动能力和坡度；对典型成年自行车骑行者、湿路条件通常使用2.5 s感知—制动反应时间，在骑行者已经预期需要制动的场景中可使用1.5 s。

来源：TxDOT《Bicycle Stopping Sight Distance》：<https://www.txdot.gov/manuals/des/rdw/chapter-18-bicycle-facilities-/18-3-elements-of-design.html>

因此2.5 s的适用对象和边界是：

- 典型成年自行车骑行者；
- 停车视距设计；
- 非预期障碍条件；
- 资料给出的表格以湿路条件为基础；
- 表示从感知道路危险到开始制动的设计反应过程。

它不能直接证明：

- 电动自行车所有速度下都适用；
- 头盔、手腕或车把振动的反应时间等于2.5 s；
- 所有年龄、注意力和身体条件都相同；
- 2.5 s已经包含完整车辆减速和停车过程。

骑行者振动预警研究表明，振动和声音会影响反应时间，而且声音在紧急场景中可能比振动更快；反应还受到警告位置、场景和学习效应影响。来源：Strohaeker等，2022，62名参与者试验场研究：<https://doi.org/10.1016/j.trf.2022.08.006>

所以本项目应将实际振动反应时间记为：

\[
T_{haptic,P95}
\]

它必须通过实际马达位置、实际振动模式和目标用户测试得到。在完成测试前，2.5 s只能作为有适用边界的保守设计参考，不能称为本项目振动反应时间实测值。

### 3.2 TTC的作用

TTC描述在当前距离和相对速度保持不变时预计发生冲突的剩余时间：

\[
TTC=\frac{d}{v_{closing}}
\]

TTC是紧迫性指标，不是事故概率，也不能单独证明能否完成停车。停车可行性还必须考虑系统延迟、人的反应和可用制动能力。

## 4. 雷达快速安全通道

雷达线程必须独立于视觉线程运行：

```text
雷达采样 → 数据有效性 → 路径门控 → TTC/所需减速度 → 风险升级 → 马达
                                  ↑
                        不等待目标检测和分割
```

视觉线程异步运行：

```text
摄像头 → NPU检测 + GPU分割 → 发布最新视觉证据
```

风险主线程可以读取最近一次未过期的视觉结果用于解释和非紧急辅助，但雷达高风险不得等待视觉完成。即使视觉卡顿、失败或被禁用，雷达安全通道仍必须按本周期数据触发马达。

应分别测量：

\[
L_{radar\rightarrow motor,P95}=P95(t_{motor\_GO}-t_{radar\_sample})
\]

\[
L_{camera\rightarrow motor,P95}=P95(t_{motor\_GO}-t_{camera\_capture})
\]

风险物理模型使用雷达到马达P95；摄像头到马达P95用于描述完整多模态演示链路性能。

## 5. 雷达目标有效性

目标进入规则模型前必须通过以下检查：

1. 雷达串口和帧校验正常；
2. `radar_valid=true`；
3. 样本时间戳存在且未过期；
4. 目标状态不是协议定义的异常、无效或删除状态；
5. 距离位于设备经说明书或实测确认的有效范围 `[d_min, d_max]`；
6. 方位角位于经说明书或实测确认的有效范围 `[theta_min, theta_max]`；
7. 如果设备确实提供有物理含义的置信度，则满足 `confidence >= confidence_min`；
8. 相对速度超过静止噪声门限；
9. 目标通过动态路径走廊检查。

这些上下限必须来自雷达说明书或本机标定。若LD2451协议没有可解释的目标置信度，不能虚构置信度，应删除该门控并使用帧校验、目标状态、持续跟踪和测量范围判断。

雷达静止速度噪声门限应通过静态测试得到：

\[
v_{noise}=P95(|v_{relative}|\mid 自行车和目标均静止)
\]

只有：

\[
v_{closing}=-v_{relative}>v_{noise}
\]

才计算TTC。

## 6. 动态路径冲突包络

### 6.1 安装偏移符号

采用车体中心为零、右正左负。雷达向左偏5.5 cm，因此：

\[
x_{mount}=-0.055m
\]

雷达目标相对雷达的横向位置：

\[
x_{radar}=d\sin(\theta)
\]

目标相对车体中心的位置必须写为：

\[
x_{bike}=x_{mount}+x_{radar}
\]

例如车体中心正前方目标相对左置雷达会出现在雷达右侧约0.055 m，代入后应得到接近零。这个实例必须加入单元测试，防止符号再次写反。

### 6.2 最小走廊不是完整安全走廊

上一版：

\[
0.66/2+0.025+0.005=0.36m
\]

只能表示“车体静态半宽 + 已知横向误差 + 安装测量误差”，不能覆盖完整碰撞包络。

完整进入边界应为：

\[
W_{enter}(d)=
\frac{W_{dynamic}}{2}
+\frac{W_{object}}{2}
+M_{clearance}
+E_{mount}
+E_{lateral}
+d\tan(E_{angle})
+E_{reflection}
\]

各项含义：

- `W_dynamic`：车把、骑手肘部、货箱和骑行摆动形成的动态最大宽度；
- `W_object`：障碍物横向宽度；
- `M_clearance`：允许的最小擦碰安全余量；
- `E_mount`：安装位置误差；
- `E_lateral`：雷达横向测量误差；
- `E_angle`：雷达角度误差，随距离形成横向误差；
- `E_reflection`：雷达反射点与物体几何边界不一致造成的误差。

在没有外参和目标宽度估计时，雷达点不能代表物体几何中心。因此0.36 m只能作为最小点目标进入门，不能称为完整安全边界。

如果雷达能输出目标簇宽度，应直接使用测得宽度；如果只能输出单反射点，则需要根据保护对象类别或保守目标宽度假设设置 `W_object`，并明确该参数来源。没有来源时不得填任意数字。

转弯场景需要未来轨迹或转向输入。当前无IMU、转角和可靠轨迹估计时，本模型只适用于前向直行/小摆动场景。

## 7. 从“来不及线”改为制动可行性边界

高风险不能仅使用：

\[
TTC\le T_{reaction}+L_{system,P95}
\]

因为该条件触发时没有为减速和避让留下时间。

更合理的判定是先计算在系统延迟和人员反应之后剩余的有效距离。对于路径内接近目标：

\[
d_{available}=d-v_{closing}(L_{radar\rightarrow motor,P95}+T_{haptic,P95})
\]

若 `d_available <= 0`，说明在完成系统下发和人员反应前就会发生冲突，属于极危状态。

若 `d_available > 0`，避免冲突所需的平均相对减速度为：

\[
a_{required}=\frac{v_{closing}^{2}}{2d_{available}}
\]

系统必须通过本车制动测试得到：

- `a_comfort`：骑行者可稳定、舒适执行的减速度；
- `a_emergency`：湿路或设计不利条件下仍可控制的紧急减速度P5或其他保守下界；
- 测试必须记录载荷、轮胎、路面、制动器、坡度和速度条件。

三级规则由此定义：

### 低风险

没有有效路径冲突目标，或目标所需减速度低于经测试确定的预警触发能力边界。

### 中风险：有效预警区

\[
a_{required}\ge a_{comfort}
\]

且：

\[
a_{required}<a_{emergency}
\]

含义：若不及时采取动作，所需制动力正在超过正常舒适处理能力，但仍未超过已验证的紧急制动能力。这一阶段才是有实际操作余量的有效预警区。

### 高风险：紧急制动能力边界

满足以下任一条件：

\[
d_{available}\le0
\]

或：

\[
a_{required}\ge a_{emergency}
\]

含义：完成系统响应和人员反应后，剩余距离已经不足，或所需减速度达到/超过经测试确认的紧急可控制制动能力。

这套规则不再把“已经来不及反应”当作首次高风险线，而是把制动可行性直接纳入风险判断。

如果当前来不及完成 `T_haptic`、`a_comfort` 和 `a_emergency` 测试，则不能声称三级阈值已经完成科学标定。可以运行规则框架和显示所需减速度，但应明确这些参数仍是待实测安全参数。

## 8. 报警疲劳控制

中风险不再由“任何接近目标”触发。必须同时满足：

- 目标有效且未过期；
- 目标通过动态路径冲突包络；
- 目标确实接近；
- 所需减速度达到 `a_comfort`；
- 本次不是已被状态机抑制的重复提醒。

中风险振动采用事件触发而不是每帧重复触发。一个目标进入中风险时触发一次短脉冲；只有风险明显上升、出现新的更危险目标或经过经测试确定的重复提醒周期后才再次提示。

重复提醒周期属于人机交互参数，必须通过误报、漏报、主观烦扰度和反应实验确定，不能写成没有来源的固定值。

高风险不受中风险冷却限制，可以立即打断中风险震动。

## 9. 非对称迟滞状态机

迟滞用于抵抗测量噪声，不等同于延迟风险升级。

### 9.1 升级

- 低到中：满足中风险进入条件立即升级；
- 中到高：满足高风险条件立即升级；
- 低到高：首次有效样本已经满足高风险条件时直接升级；
- 升级不等待多帧确认。

### 9.2 降级

空间迟滞：

\[
W_{exit}(d)=W_{enter}(d)+H_x
\]

其中 `H_x`应由静止目标横向抖动或重复走线测试的P95/P99获得。

风险量迟滞：

\[
a_{exit,high}=a_{emergency}-H_a
\]

只有所需减速度降低到退出边界以下才允许从高降到中。`H_a`由距离和速度噪声传播后的 `a_required`波动统计确定。

目标短暂丢失：

- 不立即切换低风险或静默；
- 进入 `temporarily_unknown`；
- 在 `T_dropout_hold` 内保持上一警告状态或至少保持状态指示；
- 超时后若雷达仍无效，转为 `unknown`，而不是低风险。

`T_dropout_hold`应由真实雷达短时丢失持续时间分布确定，不得随意填写。

## 10. 视觉模块当前职责

目标检测与道路分割仍正常运行，用于：

- Dashboard场景解释；
- 记录障碍物、检测框、可行驶区域和视觉有效性；
- 提供与雷达同时间段的一致性证据；
- 为外参标定和后续学习模型保留数据。

当前没有雷达—相机外参，因此不能可靠确认某个视觉框就是某个雷达目标，也不能用视觉目标宽度修正该雷达点的动态走廊。

视觉结果当前不得：

- 压制雷达高风险；
- 通过固定权重改变风险等级；
- 用单帧框面积或底部位置估算真实距离；
- 用单帧 `drivable_area_ratio`触发高风险。

准确表述为：

> 雷达快速安全通道承担实时制动可行性判断，异步视觉通道提供障碍物和道路场景辅助证据；完成外参标定后再升级到目标级关联。

## 11. 马达策略

- 低风险：静默；
- 中风险：一次短促、可辨识的注意提示；
- 高风险：立即持续强震，并打断中风险模式；
- `unknown`：不能伪装为低风险，应有独立故障指示；
- 马达命令失败时记录 `motor_valid=false` 和 `warning_delivery_valid=false`。

具体效果ID、脉冲长度、振动位置和重复策略必须通过实际佩戴实验确定。已有骑行者研究表明，声音与振动的反应表现可能不同，紧急场景可考虑声音与振动并行，而不能假设振动一定最快。

## 12. 风险计算伪代码

```python
def radar_fast_path(radar, params, previous_state):
    if not radar.valid or radar.is_stale:
        return hold_or_unknown(previous_state)

    candidates = []
    for target in radar.targets:
        if not protocol_and_range_valid(target, params):
            continue

        closing_speed = -target.relative_speed_mps
        if closing_speed <= params.radar_velocity_noise_p95:
            continue

        radar_x = target.distance_m * sin(radians(target.angle_deg))
        bike_x = -0.055 + radar_x
        enter_width = dynamic_corridor_width(target.distance_m, target, params)

        if not path_gate_with_hysteresis(bike_x, enter_width, previous_state, params):
            continue

        response_time = params.radar_to_motor_p95_s + params.haptic_response_p95_s
        available_distance = target.distance_m - closing_speed * response_time

        if available_distance <= 0:
            required_decel = float("inf")
        else:
            required_decel = closing_speed ** 2 / (2 * available_distance)

        candidates.append((target, required_decel, available_distance))

    if not candidates:
        return downgrade_with_hysteresis(previous_state, params)

    critical = max(candidates, key=lambda item: item[1])
    required_decel = critical[1]

    if required_decel >= params.emergency_decel:
        return HIGH(critical, "emergency_braking_capacity_reached")

    if required_decel >= params.comfort_decel:
        return MEDIUM(critical, "effective_early_warning")

    return LOW("required_deceleration_below_warning_boundary")
```

## 13. 必须实测或查证的参数

| 参数 | 获得方式 | 未获得前的处理 |
|---|---|---|
| `L_radar_to_motor_P95` | DK-2500真实雷达至DRV2605 GO时间戳 | 不宣称最终风险时间边界 |
| `T_haptic_P95` | 实际振动位置、模式和目标骑行者反应实验 | 2.5 s仅作有边界的保守参考 |
| `a_comfort` | 实车、载荷和路面制动测试 | 不宣称中风险阈值已标定 |
| `a_emergency` | 湿路/不利条件紧急制动能力保守下界 | 不宣称高风险阈值已标定 |
| `v_noise` | 静止雷达速度噪声P95 | 不随意填写最小接近速度 |
| `E_angle` | 雷达说明书或角度标定 | 0.36 m只能称最小走廊 |
| `W_dynamic` | 骑行摆动、车把、肘部和载荷实测 | 不宣称完整车体包络 |
| `W_object/E_reflection` | 目标簇宽度、类别或保守设计对象 | 雷达点不能代表物体中心 |
| `M_clearance` | 项目安全需求或擦碰试验标准 | 不随意增加安全余量 |
| `H_x/H_a/T_dropout_hold` | 雷达噪声和丢失持续时间统计 | 保留待标定状态 |
| 雷达有效范围/方位/状态 | 厂家说明书与本机测试 | 不让越界目标进入规则 |

`risk_score`在没有标注和概率校准时应为 `NULL`，或改名为仅供界面排序的 `risk_index`，不得解释为事故概率。

## 15. 对外表述

> 系统采用雷达快速安全通道与异步视觉辅助通道。雷达目标首先经过协议有效性、测量范围、前向方位、接近速度和动态路径包络检查，再根据系统P95延迟、骑行者响应时间和实车制动能力计算剩余有效距离及避免冲突所需减速度。所需减速度达到正常制动能力时进入有效预警区，达到紧急制动能力或剩余距离不足时进入高风险。风险升级即时执行，降级采用由雷达噪声与短时丢失统计得到的非对称迟滞。视觉检测和道路分割当前用于场景解释与数据记录，不通过未经标定的权重压制雷达紧急报警。

如果振动反应和制动能力尚未完成实测，应如实说明规则框架、传感器链路和参数测量方法已经建立，但不能把待测参数描述为已验证的安全常数。
