# RiderGuardian 比赛版本风险规则模型

## 1. 模型定位

比赛版本保留低、中、高三级输出，但不将其解释为完整制动安全等级：

| 系统等级 | 状态含义 | 马达输出 |
|---|---|---|
| 低风险（level 0） | 当前未触发前向雷达提醒，不代表绝对安全 | 静默 |
| 中风险（level 1） | 前向点目标门控内存在有效接近目标，提示注意 | 短促震动 |
| 高风险（level 2） | TTC进入反应时间紧迫参考区，立即强提醒 | 持续强震 |
| unknown | 雷达无效、过期或目标状态异常，当前不可判定 | 独立故障提示，不伪装成低风险 |

模型不使用未经标定的模态权重、事故概率、制动能力阈值或完整动态碰撞包络。准确定位为：

> 基于雷达TTC的前向冲突紧迫性提醒模型。

系统能够产生注意和紧急两级提醒，但不声称完成制动安全判定、停车距离保证或安全认证。

## 2. 当前系统条件

- 平台：Intel DK-2500。
- 雷达：HLK-LD2451。
- 目标检测：YOLO26n_v2 INT8，NPU约21 ms。
- 道路分割：road-segmentation-adas FP16，GPU约114 ms。
- 视觉推理合计约135 ms/帧；正式端到端性能以DK-2500实测P95为准。
- 车体与骑行者测量宽度：0.66 m。
- 原型点门控横向工程余量：0.025 m。该值不是手册声明的全距离横向精度。
- 雷达位于车体中心左侧约0.055 m。
- 安装位置测量不确定度约0.005 m。
- 当前没有可靠本车速度、目标绝对速度、本车制动能力和目标运动类型。
- 当前没有雷达—相机外参。
- IMU已从比赛版本中移除。

### 2.1 LD2451手册能够支持的参数

根据海凌科《HLK-LD2451车辆状态检测模组说明书》V1.03（2024-08-21）：

- 产品目标应用为室外车辆目标检测；
- 最远探测距离为100 m；
- 最远检测距离可配置，手册配置说明给出的范围为0～100 m；
- 探测视场为水平±15°、垂直±7°；
- 检测到目标时模组约每100 ms扫描并输出一次；未检测到目标时约每1 s输出一次；
- 检测速度配置范围为0～120 km/h；
- 灵敏度包含累计触发次数和信噪比阈值，累计触发次数会直接影响目标首次上报时间；
- 手册要求安装牢固稳定，雷达自身晃动会影响检测效果；背面运动目标可能被天线背瓣检测。

手册没有给出：

- 2.5 cm横向测量精度；
- 距离测量误差；
- 角度测量误差；
- 雷达反射点与目标几何中心误差；
- 对行人、路障等非车辆目标的性能保证。

因此，文档中的0.025 m只能称为当前原型的点门控横向工程余量，不能写成厂家标称精度。若后续完成横向重复测量，应单独记录测试距离、目标、样本数、均值、P95和最大误差，再决定是否将其改称本机实测横向误差。

手册正文只明确说明串口输出目标速度、距离和运动方向，性能表给出水平探测视场±15°，但未给出角度测量精度。当前程序解析得到的逐目标角度字段属于项目协议实现，必须通过串口协议资料和定点角度测试单独验证，不能仅凭V1.03说明书证明其精度。

## 3. 明确移除相对减速度规则

以下内容不进入比赛版本运行规则：

```text
d_available
a_required
a_comfort
a_emergency
制动可行性边界
舒适制动边界
紧急制动能力边界
```

移除原因是当前缺少：

- 可靠本车速度；
- 目标绝对速度；
- 目标运动类型；
- 本车制动能力；
- 目标未来运动假设；
- 不同载荷、路面和速度条件下的制动测试。

LD2451当前主要提供相对运动信息，系统尚不能稳定区分静止障碍、同向慢车和迎面目标。因此，比赛版本不把等效相对减速度解释为本车制动需求，也不使用其决定风险等级。

在后续研究中，只有在获得本车速度、目标速度、目标类型和本车制动能力后，才可以进一步研究避免冲突所需减速度。相关公式不进入当前程序和当前答辩的已实现功能范围。

## 4. 雷达快速安全通道

雷达判断必须先于视觉推理：

```text
雷达采样
  → 有效性检查
  → 最小点目标前向门控
  → 接近状态与TTC
  → 低/中/高判断
  → 马达命令
```

视觉链路异步运行：

```text
摄像头
  → NPU目标检测
  → GPU道路分割
  → Dashboard与辅助证据
```

视觉卡顿、失败或未启用时，雷达紧急判断仍然必须运行，不能等待约135 ms视觉处理完成。

风险阈值使用雷达到马达命令的P95延迟：

\[
L_{radar\rightarrow motor,P95}
=P95(t_{motor\_GO}-t_{radar\_sample})
\]

摄像头到马达P95可作为完整演示链路性能指标，但不能代替雷达到马达P95修正TTC。

## 5. 雷达数据有效性

雷达样本进入规则模型前必须满足：

1. 串口连接正常；
2. 数据帧解析和校验成功；
3. `radar_valid=true`；
4. 样本时间戳存在；
5. 样本未超过允许时效；
6. 目标状态不是协议定义的异常、无效或删除状态；
7. 距离位于说明书或本机受控测试确认的有效范围；
8. 方位角位于说明书或本机受控测试确认的有效范围；
9. 若设备提供有明确物理意义的置信度，则通过置信度门控。

如果LD2451协议没有可解释的置信度，不能虚构该字段，应依靠帧校验、目标状态、有效范围和时序稳定性。

手册给出的水平探测视场为±15°，因此比赛版本的前向角度门控不得超出该手册范围；若程序使用逐目标角度参与横向位置计算，还必须先通过本机定点角度测试确认符号和可重复性。

帧级异常与目标级异常必须分开处理：

- 雷达整帧失效、校验失败或样本过期：输出 `unknown`；
- 雷达明确报告目标列表为空：输出低风险（level 0）；
- 单个目标存在字段缺失、非有限数值、距离/角度越界或异常状态：只丢弃该目标，继续处理同帧其他目标；
- 雷达报告存在目标，但同帧全部目标都因数据异常被丢弃：输出 `unknown/degraded`，不能当作正常低风险；
- 同帧仍存在至少一个有效目标时，无效目标数量单独记录，风险判断只使用有效目标。

雷达样本年龄为：

\[
Age_{radar}=t_{decision}-t_{radar\_sample}
\]

比赛版本根据手册输出周期设置工程容错值：有目标时使用 `target_stale_ms=500`（约100 ms周期的5倍）；无目标通信监测使用 `radar_communication_watchdog_ms=2000`（约1 s周期的2倍）。两者都是工程容错值，不是厂家规定值，也不写成本项目丢帧分布实测结果。雷达超时时进入 `unknown`，不能输出正常低风险。

无目标距离和无有效TTC在内部统一使用 `None/NULL`。历史数据中的 `-1` 进入规则模型前必须转换，不能参与数值比较。

## 6. 接近速度数学有效性

项目内部统一约定：

```text
relative_speed_mps < 0：接近
relative_speed_mps = 0：相对距离基本不变
relative_speed_mps > 0：远离
```

LD2451内部已经提供最小检测速度配置，低于设备配置速度的目标由雷达内部忽略。比赛版本不再叠加无法实测的软件速度噪声门限。

接近速度定义为：

\[
v_{closing}=-v_{relative}
\]

软件只保留TTC计算必需的数学条件：

\[
isfinite(v_{closing})\quad\text{且}\quad v_{closing}>0
\]

该条件不是经验速度阈值，只用于排除非有限数值、静止和远离目标。雷达APP中的最小检测速度配置应记录在演示配置说明中。

## 7. 最小点目标前向门控

### 7.1 名称与作用

比赛版本不使用“完整动态走廊”“安全碰撞包络”等名称。当前0.36 m参数统一称为：

> 最小点目标前向门控半宽。

它只用于判断雷达反射点是否靠近当前车体正前方，以减少明显路边目标误触发。

它不能表示：

- 障碍物整体与车体是否重叠；
- 完整安全间距；
- 障碍物自身宽度；
- 骑行动态摆动包络；
- 转弯路径预测；
- 雷达反射点就是物体几何中心。

### 7.2 坐标与安装偏移

使用车体中心为零、左负右正的统一坐标。

雷达安装位置：

\[
x_{mount}=-0.055m
\]

雷达目标横向位置：

\[
x_{radar}=d\sin(\theta)
\]

目标相对车体中心的位置：

\[
x_{bike}=x_{mount}+x_{radar}
\]

项目雷达驱动已经通过 `angle_sign` 将原始角度转换成左负右正，因此此处使用加法。车体中心正前方目标相对左置雷达应出现在雷达右侧约0.055 m，代入后得到接近零；该场景应保留为单元测试。

### 7.3 点目标门控半宽

\[
W_{point}=0.66/2+0.025+0.005=0.36m
\]

门控条件：

\[
|x_{bike}|\le0.36m
\]

对外表述：

> 当前缺少目标宽度和雷达—相机外参，因此系统使用基于实测车体宽度的最小点目标前向门控，降低明显路边目标的误触发。它不是完整碰撞走廊；对于大型目标边缘、横向切入和转弯场景仍可能漏判。

其中0.025 m是比赛原型的横向工程余量，不是LD2451手册标称横向精度；0.005 m来自雷达左偏5～6 cm安装位置测量范围的一半。

目标宽度、角度误差随距离放大、骑行摆动、安全余量、反射点偏差和转弯轨迹统一列入未来工作，不进入当前运行伪代码。

## 8. TTC与紧迫参考线

对每个有效、接近且进入点目标门控的目标：

\[
TTC_i=\frac{d_i}{v_{closing,i}}
\]

当前周期采用最小TTC：

\[
TTC_{min}=\min(TTC_1,TTC_2,\ldots,TTC_n)
\]

紧迫参考线定义为：

\[
T_{urgent}=T_{reference}+L_{radar\rightarrow motor,P95}
\]

其中：

\[
T_{reference}=2.5s
\]

2.5 s来源于TxDOT/AASHTO自行车停车视距设计中，针对典型成年自行车骑行者、非预期障碍情景使用的感知—制动反应时间参考。来源：<https://www.txdot.gov/manuals/des/rdw/chapter-18-bicycle-facilities-/18-3-elements-of-design.html>

必须明确：

- 2.5 s不是本项目头盔振动反应时间实测值；
- `T_urgent`不包含完整车辆减速、停车或避让时间；
- `T_urgent`不是安全停车阈值；
- `T_urgent`只表示在当前匀速假设下，剩余冲突时间已经进入反应时间紧迫参考区。
- 该参考线不是停车安全阈值，也不表示系统能够保证完成减速或避让。

## 9. 比赛版本配置提醒范围

为避免对雷达探测范围内所有远距离接近目标持续提醒，中、高风险均限制在LD2451 APP当前配置的最远检测距离内：

\[
d\le d_{max,configured}
\]

该范围在程序与数据字段中统一命名为 `configured_warning_range_m`。它不能称为安全距离或稳定跟踪实测范围，只能称为：

> 与LD2451 APP最远检测距离配置一致的比赛版本工作范围。

该值直接读取或设置于LD2451 APP，并在程序启动参数中使用相同值。它属于设备配置，不表示本项目完成了距离精度或稳定跟踪验证。

## 10. 三级风险规则

### 10.1 低风险（level 0）

条件：雷达有效，但没有目标同时满足有效性、接近速度、点目标门控和原型提醒范围要求。

含义：当前未触发雷达前向提醒，不代表绝对安全。

### 10.2 中风险（level 1）

条件：

- 雷达样本有效且未过期；
- 目标测量有效；
- 接近速度是有限数值且大于零；
- 反射点位于最小点目标前向门控；
- 目标距离位于本机原型有效提醒范围；
- `TTC > T_urgent`。

含义：前向点目标门控内存在有效接近目标，提醒骑行者注意。

### 10.3 高风险（level 2）

条件：候选目标满足有效性、接近和点目标门控，并且：

\[
TTC\le T_{urgent}
\]

高风险除TTC条件外，还必须满足：

\[
d\le d_{max,configured}
\]

含义：在当前相对运动保持不变的假设下，且目标位于比赛版本配置工作范围内，剩余冲突时间已经进入反应时间紧迫参考区，需要立即强提醒。

高风险不解释为完整制动能力不足，也不表示系统能够保证停车。

### 10.4 unknown

以下情况进入 `unknown`：

- 雷达失效；
- 样本过期；
- 帧解析异常；
- 目标状态异常；
- 关键测量字段非法。

`unknown`不能映射成正常低风险。数据库仍可保存上一次风险等级，但必须同时保存 `radar_valid=false` 和明确的异常原因；Dashboard优先显示不可判定状态。

## 11. 状态转换与通信看门狗

状态稳定不增加风险升级延迟：

```text
低 → 中：满足中风险条件立即升级
中 → 高：满足高风险条件立即升级
低 → 高：首次有效样本已满足紧迫条件时直接升级
```

比赛版本不引入无法测量的短时保持参数：

- 雷达明确报告无目标、目标远离、超出点门控或超出配置工作范围时输出低风险；
- 有目标状态连续500 ms没有新帧时进入 `unknown`；
- 无目标状态连续2000 ms没有新帧时进入 `unknown`；
- 单个目标异常只丢弃；全部目标异常时进入 `unknown/degraded`；
- 高风险可以立即打断中风险马达模式。

500 ms和2000 ms分别是手册约100 ms有目标周期的5倍、约1 s无目标周期的2倍，属于工程通信容错和看门狗参数，不是厂家规定值，也不参与TTC等级边界计算。

## 12. 视觉模块职责

视觉检测和道路分割当前用于：

- Dashboard显示与场景解释；
- 保存障碍物、检测框、置信度和可行驶区域；
- 记录与雷达同时间段的辅助证据；
- 为后续外参标定和模型训练留存数据。

当前视觉不得：

- 压制雷达高风险；
- 通过固定权重改变风险等级；
- 用单帧目标框面积估计距离；
- 用单帧可行驶区域比例触发高风险；
- 声称视觉框与某个雷达目标已经精确对应。

准确表述为：

> 雷达快速通道承担实时TTC紧迫性提醒，视觉通道提供障碍物与道路场景辅助证据；完成雷达—相机外参和关联验证后再升级目标级融合。

## 13. 马达输出

```text
level 0：静默
level 1：短促震动，注意提醒
level 2：持续强震，紧急提醒
unknown：独立故障指示，不能伪装成低风险
```

具体效果ID、脉冲长度和重复周期属于人机交互参数。比赛版本可以展示既有三级模式，但不能声称其已经通过骑手人群反应实验验证。

马达失败时记录：

```text
motor_valid = false
warning_delivery_valid = false
```

## 14. 当前运行伪代码

```python
def calculate_risk(radar, previous_state, params):
    if not radar.valid or radar.is_stale:
        return UNKNOWN("radar_invalid_or_stale")

    candidates = []

    for target in radar.targets:
        if not target_measurement_valid(target, params):
            continue

        closing_speed = -target.relative_speed_mps
        if not isfinite(closing_speed) or closing_speed <= 0:
            continue

        # 雷达驱动已统一成左负右正坐标。
        lateral_m = (
            params.radar_mount_x_m
            + target.distance_m * sin(radians(target.angle_deg))
        )

        if abs(lateral_m) > params.point_gate_half_width_m:
            continue

        ttc_s = target.distance_m / closing_speed
        candidates.append((target, ttc_s, lateral_m))

    if not candidates:
        return LOW("no_candidate_in_configured_scope")

    critical = min(candidates, key=lambda item: item[1])
    target, ttc_s, lateral_m = critical

    urgent_ttc_s = (
        params.urgent_reference_s
        + params.radar_to_motor_p95_s
    )

    if (
        target.distance_m <= params.configured_warning_range_m
        and ttc_s <= urgent_ttc_s
    ):
        return HIGH(
            critical,
            "ttc_entered_urgency_reference",
        )

    if target.distance_m <= params.configured_warning_range_m:
        return MEDIUM(
            critical,
            "approaching_target_in_point_gate",
        )

    return LOW("target_outside_prototype_warning_range")
```

## 15. 当前所需参数及来源

| 参数 | 当前值或来源 | 含义 |
|---|---|---|
| `radar_mount_x_m` | -0.055 m，实测安装位置 | 雷达相对车体中心偏移 |
| `point_gate_half_width_m` | 0.36 m：0.33 m车体半宽 + 0.025 m工程余量 + 0.005 m安装测量不确定度 | 最小点目标前向门控半宽，不是完整碰撞包络 |
| 软件速度门限 | 取消；使用LD2451内部最小检测速度配置 | 软件只检查接近速度为有限数值且大于零 |
| `target_stale_ms` | 500 ms：手册有目标约100 ms周期的5倍 | 工程容错值，不是厂家规定值 |
| `radar_communication_watchdog_ms` | 2000 ms：手册无目标约1 s周期的2倍 | 工程通信看门狗，不是厂家规定值 |
| `configured_warning_range_m` | LD2451 APP最远检测距离配置 | 比赛版本工作范围，不是安全距离或稳定跟踪实测范围 |
| `urgent_reference_s` | 2.5 s设计参考 | 反应时间紧迫性设计参考，不是停车安全阈值 |
| `radar_to_motor_p95_s` | DK-2500真实链路测试 | 修正雷达数据到马达下发延迟 |

## 17. 文档与正式程序一致性验收

本节是答辩前的强制验收清单。只有逐项通过代码检查和真机测试后，才能对外声明本规则已经接入正式运行入口：

- 正式入口读取雷达后立即完成TTC判断和马达下发，不等待目标检测或道路分割；
- 雷达整帧无效或样本过期时，Dashboard显示 `unknown`，马达与界面不得将其当作正常低风险；
- 单个异常目标只被丢弃；雷达报告有目标但全部异常时显示 `unknown/degraded`；
- 安装偏移使用左负右正坐标，车体中心正前方测试目标经过 `-0.055 + d*sin(theta)` 修正后应接近零；
- 当前等级只由本文件定义的雷达有效性、设备配置工作范围、点目标门控和TTC规则产生；
- 正式入口不再使用旧加权 `risk_score` 决定低、中、高等级；
- 中、高风险均满足 `distance <= configured_warning_range_m`；
- TTC规则的输出同时控制马达和Dashboard，两者的等级、原因、关键目标与TTC一致；
- Dashboard明确显示 `risk_status`、`risk_level`、`risk_reason`、关键目标距离、TTC、紧迫参考线和雷达有效性；
- 通过视觉线程故意延迟或关闭测试，验证雷达紧急提醒延迟不随视觉推理时间增加；
- 通过无目标、单个异常目标、全部异常目标、雷达过期、中风险目标和高风险目标六类受控用例。

若任一项未通过，文档中只能描述为设计规则或待接入功能，不能写成正式程序已经实现。

### 17.1 正式入口

比赛版规则已接入 `run_dashboard.py --dashboard-mode real`。启用时只需显式提供APP配置范围和本机实测P95；500/2000 ms看门狗已有手册周期依据的工程默认值：

```bash
python run_dashboard.py \
  --dashboard-mode real \
  --profile dk2500 \
  --enable-vision \
  --enable-risk-rule \
  --motor-mode real \
  --confirm-motor-real \
  --configured-warning-range-m <LD2451 APP最远检测距离米> \
  --radar-to-motor-p95-ms <雷达到马达实测P95毫秒>
```

两个尖括号参数不能直接照抄：提醒范围应与LD2451 APP配置一致，P95应替换为DK-2500实测结果。若只验证Dashboard而不驱动真实马达，可将 `--motor-mode real --confirm-motor-real` 改为 `--motor-mode mock`。

代码实现位置：

- `src/fusion/physical_risk_rule.py`：TTC紧迫性规则、点目标门控及帧/目标异常分流；
- `src/dashboard/real_sensor_state.py`：雷达先于GPS和视觉的快速通道、马达下发与Dashboard状态；
- `src/sensors/radar_reader.py`：最近有效帧缓存及基于样本年龄的过期支持；
- `src/dashboard/static/index.html`：`unknown/degraded`独立显示；
- `src/dashboard/dashboard_recorder.py`：记录与Dashboard同源的风险决策；
- `scripts/test_competition_risk_rule.py`：规则边界测试；
- `scripts/test_dashboard_competition_pipeline.py`：视觉延迟不阻塞雷达马达测试。

## 19. 答辩表述

> 比赛版本采用可解释的雷达TTC紧迫性提醒模型，并保留低、中、高三级展示。系统首先检查雷达数据有效性和新鲜度，再使用基于实测车体宽度的最小点目标前向门控过滤明显路边反射点。对门控内的有效接近目标计算TTC：目标位于LD2451 APP当前配置的比赛工作范围内时可输出注意提醒，TTC进入由2.5秒自行车感知—制动反应设计参考和雷达到马达实测P95延迟组成的紧迫区时输出紧急提醒。配置范围不是安全距离或稳定跟踪实测范围；该模型也不声称完成停车安全判定。
