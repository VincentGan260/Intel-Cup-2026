## 一、笔记本环境结论

### 1. 必须使用项目 `.venv`

- 全局 Anaconda 环境缺少部分项目依赖，不能用于判断项目是否可运行。
- 项目 `.venv` 已确认可以导入 `cv2`、`fastapi` 和 `uvicorn`，Dashboard 录制与韧性测试已通过。
- `requirements.txt` 已统一包含 `requirements/dashboard.txt`，供新环境一次性安装。

上机检查：

```powershell
.\.venv\Scripts\python.exe -c "import sys, cv2, fastapi, uvicorn; print(sys.executable); print(cv2.__version__)"
```

处理原则：开发机测试与 Dashboard 均使用 `.venv\Scripts\python.exe`，避免“安装成功但程序使用另一个环境”。

### 2. NPU 初始化失败是笔记本的预期降级

- 普通笔记本运行正式视觉配置时，OpenVINO NPU 插件会报告无法识别设备并使视觉适配器进入降级状态。
- 这不代表 DK2500 的 NPU 配置有误，也不应为了在笔记本上强行推理而修改正式 NPU/GPU 部署契约。
- 笔记本验收的是降级后雷达规则、时间戳、录制回放和 Dashboard 仍可工作；视觉真实性能留到 DK2500 验收。
- Ultralytics 配置目录已固定到项目内 `tmp/ultralytics`，测试默认图像已改为本地合成帧，不再依赖联网下载。

## 二、测试脚本路径问题

### 3. 录制测试曾固定使用无权限的 `C:\tmp`

- 失败现象：`scripts/test_dashboard_recording_mock.py` 创建 `C:\tmp\intelcup_dashboard_recording_mock` 时出现 `PermissionError: [WinError 5]`。
- 影响范围：当前环境中的 Dashboard 录制测试无法完成。
- 对风险判断的影响：无。该问题不改变雷达、视觉、GPS或融合结果。
- 对实际系统的潜在影响：如果正式录制目录同样不可写，帧、传感器数据和会话记录将无法保存，但实时预警仍应独立运行。

推荐处理：将测试临时目录改为项目内的 `tmp` 或通过系统临时目录API生成，不再写死 `C:\tmp`。正式录制前还需验证目标目录存在、可写且剩余空间充足。

当前整改：测试目录已改为项目内的 `tmp/intelcup_dashboard_recording_mock`，并由 `.gitignore` 排除运行产物。

## 四、验收标准

- 同一 Python 解释器可以导入项目全部运行时依赖。
- 完整 Dashboard 测试不再因缺包或目录权限退出。
- 视觉不可用时系统明确显示降级状态，雷达快速高风险通道仍可工作。
- GPS不可用时速度修正系数回到 `1.0`，不改变雷达或视觉原始判断。
- Dashboard不可访问不能阻塞底层传感器采集、风险仲裁和马达报警线程。
- 录制失败必须可诊断，不能拖慢或中断实时预警。
