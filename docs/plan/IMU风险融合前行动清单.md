# IMU风险融合前行动清单

## 目标

确认WT61C在最终安装状态下的数据方向、零偏、更新周期和同步性。完成前，IMU不得参与低/中/高风险仲裁；现有 `brake_score`、`bump_score`、`tilt_score` 只作为调试字段，不作为标定真值。

## 1. 安装与配置

1. IMU固定在最终安装位置，记录接口朝向和车体前、左、上三个方向。测试后不要再改变安装角度。
2. 将IMU连接到实际运行主机或DK2500，确认供电、GND和串口稳定。
3. Windows当前配置为 `COM8 / 115200`。DK2500的 `configs/sensor_ports.yaml` 目前缺少 `imu` 段，需要填写真实端口：

```yaml
dk2500:
  imu:
    port: "/dev/ttyIMUWT61C"  # 使用现场确认的端口或稳定udev链接
    baudrate: 115200
    timeout: 0.1
```

不要在未确认设备映射时照抄端口名称。

## 2. 连通性预检

在项目根目录运行：

```bash
python scripts/preflight_dk2500.py --profile dk2500 --loops 30
```

Windows调试改用：

```bash
python scripts/preflight_dk2500.py --profile windows --loops 30
```

最低要求：串口成功打开、无持续解析异常、`valid_count` 明显大于0。注意：当前预检只打印最后一组 `roll/pitch/yaw`，只能证明基本连通，不能证明加速度、角速度与姿态同步。

## 3. 必须记录的字段

以CSV或JSONL连续记录，不能只截图终端：

```text
wall_timestamp
monotonic_timestamp_ns
valid
roll, pitch, yaw
gyro_x, gyro_y, gyro_z
acc_x, acc_y, acc_z
brake_score, bump_score, tilt_score
```

若修改读取器，额外记录角度包、角速度包、加速度包各自的最后到达时间和样本年龄。不要把缺失字段自动写成“有效的0”。

## 4. 受控动作

每个场景开始和结束保持静止3秒，动作缓慢，确保车辆有人扶稳：

1. 水平静止20秒。
2. 缓慢向左倾斜并恢复，重复3次。
3. 缓慢向右倾斜并恢复，重复3次。
4. 缓慢前倾、后仰并恢复，各重复3次。
5. 保持车体基本竖直，向左、向右转动车头，各重复3次。
6. 轻微上下振动或模拟小颠簸，重复3次。
7. 安全条件允许时，推行直线、普通转弯和停止；暂不做故意摔车测试。

同步记录每段动作的开始时间、结束时间、方向和人工备注。

## 5. 验收项目

- 静止时确定 `roll/pitch` 零偏和波动范围。
- 确定左倾、右倾对应的 `roll` 正负方向。
- 确定前倾、后仰对应的 `pitch` 正负方向。
- 验证 `gyro_x` 与 `roll` 变化方向一致，`gyro_y` 与 `pitch` 变化方向一致。
- 确认静止时重力主要落在哪个加速度轴，单位约为 `m/s^2`。
- 统计更新间隔P50/P95/P99、最大断流时间、无效样本比例和坏校验帧数量。
- 检查普通转弯、推行和轻微颠簸是否会让现有 `tilt_score` 长时间偏高。
- 检查角度、角速度、加速度是否来自相近时刻；当前候选同步上限为 `200 ms`，最终值根据实测P95/P99确定。

## 6. 需要交付

1. 原始CSV或JSONL数据文件。
2. 场景时间段和动作说明。
3. 最终IMU端口与安装方向照片/文字说明。
4. 静止零偏、波动范围、轴正负方向、更新周期P50/P95/P99摘要。
5. 测试期间使用的代码提交号，以及所有IMU相关代码/配置修改。

完成以上交付后，再制定“早期失稳中风险”规则。已跌倒状态应进入独立事故状态，不作为高风险预警阈值。
