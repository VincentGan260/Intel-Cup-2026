# RiderGuardian 多模态风险规则改造方案（已实施）

> 本文档是比赛版本多模态预警的实施依据。核心事件、仲裁、状态机和正式Dashboard入口已按本文档接入；真机马达、雷达通信与视觉模型仍须按第14节完成上板验收。

## 1. 目标与取舍

将当前“雷达决定等级、视觉主要展示”调整为：

```text
雷达快速事件通道
+ 视觉路径障碍事件通道
+ 无权重、无否决事件仲裁
+ 统一预警状态机
```

为保留已实测的“主机成功解析雷达帧至DRV2605 `GO`写入”P95，雷达高风险保留直接马达快速通道，不进入事件队列等待。

```text
vision_level ∈ {0, 1, None}
radar_level  ∈ {0, 1, 2, None}
final_level  ∈ {0, 1, 2, None}
```

| 通道 | level 0 | level 1 | level 2 | None |
|---|---|---|---|---|
| 视觉 | 当前未发现路径障碍 | 发现路径相关障碍 | 当前不提供 | 无效或过期 |
| 雷达 | 当前未发现前向接近目标 | 发现前向接近目标 | TTC进入反应时间紧迫参考区 | 无效或过期 |

不引入模态权重、综合概率、未标定视觉高风险、目标级关联、新的距离/TTC变化阈值。

## 2. 参数

```text
radar_parsed_to_motor_go_p95_ms = 0.469
urgent_reference_ms = 2500
configured_warning_range_m = LD2451 APP配置值
radar_mount_x_m = -0.055
point_gate_half_width_m = 0.36

target_stale_ms = 500
vision_stale_ms = 500
release_hold_ms = 500
radar_communication_watchdog_ms = 2000
```

TTC紧迫参考始终写为：

\[
T_{urgent}=T_{reference}+L_{parsed\rightarrow motor\_GO,P95}
\]

其中0.469 ms的测量起点是主机成功解析新雷达帧的单调时间戳，终点是DRV2605 `GO`寄存器写入完成。它只补偿当前软件能够实测的解析后规则与执行链路，不包含雷达内部扫描、完整串口传输、马达机械起振和骑手反应，因此不得称为从雷达物理测量时刻开始的完整端到端延迟。

三个500 ms参数是数据时效和降级去抖参数，不是风险阈值、安全距离或厂家规定值。500 ms约对应5个雷达有目标周期和3～4个当前视觉推理周期。

## 3. 运行架构

```text
雷达线程
  → evaluate_radar
  → level 2时fast_request_high()直接写马达
  → 再发布RadarEvent
                              ┐
视觉线程                    │
  → VisionEvent ──────────────├→ 仲裁线程
周期健康检查 ──────────────────┘   → 仲裁/降级状态机
                                  → 中风险马达
                                  → Dashboard/日志
```

视觉采用“仅保留最新待处理帧”的有界队列，避免积压旧帧。

## 4. 事件结构

```python
ModalityEvent(
    source,
    source_id,
    sequence,
    capture_monotonic_ns,
    completed_monotonic_ns,
    usable,
    level,
    reason,
    details,
)
```

RadarEvent记录关键目标距离、接近速度、横向位置、TTC和目标过滤计数。VisionEvent记录源帧ID、采集/完成时间、路径障碍数及判断原因。

## 5. 雷达通道

### 5.1 雷达状态

```text
usable_target
usable_no_target
temporarily_unknown
communication_timeout
protocol_error
disconnected
```

```python
if communication_age_ms > radar_communication_watchdog_ms:
    radar_level = None
    radar_status = "communication_timeout"

elif latest_packet.explicit_no_target:
    radar_level = 0
    radar_status = "usable_no_target"

elif latest_packet.has_targets and target_age_ms <= target_stale_ms:
    radar_level = evaluate_targets(latest_packet.targets)
    radar_status = "usable_target"

else:
    radar_level = None
    radar_status = "temporarily_unknown"
```

只有成功解析并通过协议完整性检查的雷达帧才能刷新 `last_valid_radar_packet_ns`；任意串口字节不能刷新通信看门狗。

### 5.2 雷达目标和等级

目标通过数值合法性、APP工作范围、±15°方位角、0.36 m点目标门控及接近方向检查。

```python
closing_speed = -target.relative_speed_mps
if not math.isfinite(closing_speed) or closing_speed <= 0:
    continue
```

```text
无有效前向接近候选：level 0
存在有效前向接近候选：level 1
关键目标TTC进入紧迫区：level 2
```

### 5.3 高风险快速路径

```python
radar_event = evaluate_radar(frame)
if radar_event.usable and radar_event.level == 2:
    warning_state.fast_request_high(radar_event)
publish_radar_event(radar_event)
```

视觉不得否决或延迟该请求。

## 6. 视觉通道

检测与分割只要求来自同一源帧：

```python
detection.source_frame_id == segmentation.source_frame_id
```

不与摄像头当前最新帧ID比较。事件保存源帧ID及采集/推理完成单调时间。旧结果不得覆盖新结果：

```python
if event.capture_ns <= latest_vision_capture_ns:
    discard_event()
```

### 6.1 坐标和路径相关性

检测框与分割掩膜必须先映射到同一原始图像坐标系，正确处理letterbox、缩放、裁剪和图像边界。

```python
sample_y = min(height - 1, int(y2) + 1)
sample_xs = [
    clamp(int(x1), 0, width - 1),
    clamp(int((x1 + x2) / 2), 0, width - 1),
    clamp(int(x2), 0, width - 1),
]
path_related = any(drivable_mask[sample_y, x] for x in sample_xs)
```

三点采样是同帧检测和道路分割的路径相关性启发式，不等于精确落脚点、占道比例或碰撞路径判断。

### 6.2 视觉等级和时效

```text
存在路径相关障碍：level 1
不存在路径相关障碍：level 0
推理失败、帧不一致、坐标映射失败或过期：None
```

视觉当前不输出 level 2。可用性同时检查完成时间与源帧釆集时间：

```python
vision_usable = (
    event is not None
    and event.usable
    and now_ms - event.completed_ms <= vision_stale_ms
    and now_ms - event.capture_ms <= vision_stale_ms
)
```

## 7. 无权重事件仲裁

```python
available_levels = []
if radar_usable:
    available_levels.append(radar_level)
if vision_usable:
    available_levels.append(vision_level)

if not available_levels:
    final_level = None
elif 2 in available_levels:
    final_level = 2
elif 1 in available_levels:
    final_level = 1
else:
    final_level = 0
```

系统健康状态：

```python
if radar_usable and vision_usable:
    system_status = "normal"
elif radar_usable or vision_usable:
    system_status = "degraded"
else:
    system_status = "unknown"
```

输出 `radar_level`、`vision_level`、`final_level`、`system_status`、`warning_reason`、`evidence_sources`和 `both_modalities_active`。`both_modalities_active`只表示两通道同时存在风险证据，不表示发现同一目标。来源集合变化不自动触发新震动。

## 8. 并发和幂等

为保留直接高风险路径，使用共享 `WarningState`及统一 `state_lock`/`motor_lock`。

```text
current_level
last_known_level
last_processed_radar_sequence
last_processed_vision_sequence
pending_lower_level
downgrade_started_ns
last_motor_level
```

状态锁只用于短暂检查与状态转移，不得在完整马达效果期间持有。雷达快速事件按 `sequence`幂等；完整仲裁再次得到level 2时不得二次驱动。I²C寄存器操作通过同一 `motor_lock`串行化。

## 9. 预警状态机

`None`表示当前没有可用模态能够给出风险等级，不是比level 0更低的数值等级。状态机不得直接比较`None`与整数，必须先显式处理不可判定状态。

### 9.1 unknown与恢复

```python
if requested_level is None:
    system_status = "unknown"
    if current_level is not None:
        last_known_level = current_level
    current_level = None
    pending_lower_level = None
    downgrade_started_ns = None
    # 不把unknown当作level 0，不触发风险马达。
    return

if current_level is None:
    current_level = requested_level
    pending_lower_level = None
    downgrade_started_ns = None

    if requested_level == 1:
        trigger_medium_once()
    elif requested_level == 2:
        trigger_high_once()
    # requested_level == 0时只恢复正常监测。
    return
```

进入unknown时，Dashboard当前等级显示不可判定，并另存`last_known_level`；不得通过`1→0`或`2→0`的降级逻辑处理。由unknown恢复到level 1或2时立即提醒，恢复到level 0时只恢复正常监测。

### 9.2 升级

```text
0/None → 1：中风险短震一次
0/1/None → 2：立即高风险有界强震一次
```

### 9.3 同级

```text
1 → 1：不重复震动
2 → 2：不重复下发
来源变化：仅更新Dashboard/日志
```

### 9.4 通用降级保持

统一处理 `2→1`、`2→0`和 `1→0`：

```python
if requested_level < current_level:
    if pending_lower_level != requested_level:
        pending_lower_level = requested_level
        downgrade_started_ns = now_ns
    elif now_ns - downgrade_started_ns >= release_hold_ms:
        current_level = requested_level
        pending_lower_level = None
        downgrade_started_ns = None
```

降级等待期间若原等级或更高等级恢复，立即取消降级。从2降到1时停止未完成的高风险模式，不额外触发中风险短震。

### 9.5 两模态不可用

两模态都不可用时，`final_level=None`、`system_status=unknown`。当前预警字段显示不可判定，另存 `last_known_level`。不将故障伪装成低风险，也不将传感器故障当作高风险震动。

## 10. 马达策略

当前比赛版本保留现有有界效果：

```text
进入level 1：短震一次
进入level 2：有界强震一次
同级持续：不逐帧重复
```

文档不再使用“持续强震”，除非后续完成DRV2605持续模式和安全停止测试。

## 11. P95口径

```text
L_parsed→motor_GO,P95 = 0.469 ms
起点：主机成功解析新雷达帧的单调时间戳
终点：DRV2605 GO寄存器写入完成
```

该指标准确名称为“雷达帧解析完成至马达GO写入P95”，不是完整“雷达到马达P95”。它不包含雷达内部扫描周期、完整串口传输、马达机械起振、骑手反应和完整多模态系统延迟。为保留该结果，雷达level 2不得经过事件队列、视觉等待或Dashboard。

## 14. 必须验证

1. 雷达高风险不等待视觉且不经过事件队列。
2. 同一雷达高风险事件及后续仲裁不会重复驱动。
3. 无目标雷达状态在500～2000 ms内不被判为通信故障。
4. 旧目标超过500 ms进入 `temporarily_unknown`，通信超过2000 ms才进入 `communication_timeout`。
5. 视觉过期、异常慢推理、帧不一致和乱序结果均不参与仲裁。
6. 视觉单帧路径障碍触发一次中风险，持续中风险和来源变化不重复震动。
7. 状态正确完成 `2→1`、`2→0`和 `1→0`，恢复风险会取消降级。
8. 单模态失效时另一模态可提醒并重新布防，两模态失效进入unknown。
9. 状态锁不在完整马达效果期间持有，I²C写入不会并发交错。
10. 三点采样不越界，letterbox/缩放后检测框与掩膜使用同一坐标系。
11. P95脚本仍测量直接雷达高风险路径。
12. 状态机显式覆盖`None→0/1/2`和`0/1/2→None`，不对`None`与整数执行大小比较。
