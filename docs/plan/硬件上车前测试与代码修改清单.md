## 四、多模态联合采集上车前验收

### 时间戳约定（已冻结）

- `monotonic_ns`：各线程完成一次硬件读取的主机单调时钟；唯一同步依据，不受系统校时影响。
- `wall_time_ns`：同一读取完成点的系统实时时钟；用于日期、事件显示和文件追踪，不参与最近帧匹配。
- `read_start_monotonic_ns/read_end_monotonic_ns`：包围阻塞读取，用于测量驱动和调度延迟。
- `read_duration_ms`：读取耗时；上DK2500后据此评估同步误差和是否需要调低阻塞超时。
- 相机时间戳在`cap.read()`返回后记录；串口传感器在`read_once()`返回后记录。
- 当前不使用GPS PPS；GPS的NMEA UTC仅作绝对时间参考，多模态对齐使用同机`monotonic_ns`。
- 采集后允许重新调整同步阈值并重建`fusion.jsonl`，原始JSONL和图片禁止覆盖。

### 1. 30秒桌面联合录制

```bash
python scripts/record_multimodal.py --mode real --profile dk2500 --duration 30 --scene desk_test
```

测试动作：

1. 前10秒全部静止；
2. 中间10秒目标由远到近经过相机和雷达视场；
3. 后10秒轻微晃动车体，产生明显IMU变化；GPS放在可定位位置。

### 2. 离线同步与质量检查

```bash
python scripts/sync_recording.py data/recordings/<session>
python scripts/check_recording.py data/recordings/<session> --require-fusion
```

- [ ] `frames/radar/imu/gps`记录数均不为0。
- [ ] 图片缺失数为0，所有时间戳单调递增。
- [ ] 雷达匹配误差原则上不超过100ms。
- [ ] IMU匹配误差原则上不超过50ms。
- [ ] GPS匹配误差原则上不超过1000ms。
- [ ] 超时数据标记`valid=false`，不能用0伪装正常数据。
- [ ] 随机抽查至少10张图片，对照同一融合帧的雷达、IMU和GPS数据。
- [ ] 检查每路`read_duration_ms_max`；若接近或超过同步容差，先缩短串口timeout/调整读取方式再采集。

- [ ] 更新 [multimodal_recording_guide.md](../guide/multimodal_recording_guide.md) 中的最终命令和端口说明。

## 五、正式上车前机械与安全验收

- [ ] 相机和雷达刚性固定，方向不会因颠簸改变。
- [ ] 雷达前方没有金属、车筐或外壳遮挡；外壳材料可透24GHz雷达波。
- [ ] IMU刚性固定并重新做安装坐标标定。
- [ ] GPS天线朝上且远离强干扰源。
- [ ] 线缆不影响转向、刹车、车轮和骑手动作。
- [ ] 所有模块防松、防水、防短路，电源有保险或限流保护。
- [ ] 高风险场景只在封闭空场低速完成，使用纸箱/假人，不使用真人制造碰撞风险。
- [ ] 安排一名驾驶、一名场景控制、一名电脑监控；驾驶者不操作电脑。
