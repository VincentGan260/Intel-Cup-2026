# 视觉-雷达融合设计（综合风险）

> 本文确立电动车感知系统中「视觉障碍物检测 + 毫米波雷达」的融合思想、综合风险公式、
> 工程取舍与理论依据，作为开发报告「融合方法」章节 + 实现蓝图。
> 配套：视觉评测见 [`精度评测结果.md`](../精度评测结果.md)，方案原理见 [`视觉方案设计与方法论.md`](视觉方案设计与方法论.md)。

---

## 1. 背景与定位

载体为电动车（非机动车），前向感知需在端侧（DK-2500）**实时**完成。单一传感器都有盲区：

| 传感器 | 强项 | 盲区 |
|---|---|---|
| 视觉（目标检测+分割） | 知道「是什么」(人/车)、精确 2D 形状/位置、给出路面 | 只认训练过的类别、估距粗、暗光/遮挡退化、有漏检 |
| 毫米波雷达（LD2451） | 真实距离/相对速度/TTC、暗夜浓雾可用、能测**任何物理回波** | 不知道「是什么」、角分辨率粗、易有路边杂波 |

二者盲区**互补**，融合的价值正在于此。

---

## 2. 核心融合哲学

### 2.1 取并集，不取交集（recall 优先）

**任一传感器看到即视为障碍物，谁也不能否决谁。** 漏检对电动车最致命，故融合判定用 **OR** 而非 AND。
这与项目既定的**「类别无关障碍物检测」**一脉相承：**类别只决定风险高低，不决定算不算障碍物。**

### 2.2 并集保 recall，几何门控保 precision

并集会引入雷达侧的误报（护栏、路沿、路边停车、地面杂波）。若「雷达看到就报警」会频繁误震、骑手弃用。
因此加**几何门控**：所有障碍物都保留，但风险由「**在不在行进路径上 + 是否在接近 + 是否在路面上**」调制。
路边静止护栏（偏角大、不接近、不在路面）→ 风险≈0；正前方逼近的回波 → 风险高。

### 2.3 理论主线：证据占据栅格的「未知」态

雷达测到、视觉未识别的目标 **不丢弃**——它可能是：① 未训练过的障碍类型（杆/栏/落物/动物），② 或被漏检的人/车。
**证据占据栅格（Dempster-Shafer）** 把每个单元的信任质量分配到 **{Free 空 / Occupied 占据 / Unknown 未知}** 三态，
「Occupied 但 Unknown」恰好就是「有东西、但不知道是什么」。该框架把「不知道」建模为**独立状态而非直接丢弃**，
正是本融合保留「未知障碍物」的理论依据（见 §8）。

## 3. 三类融合目标及处理

| 情形 | 含义 | 处理 |
|---|---|---|
| **视觉 ∩ 雷达** | 置信最高：视觉给类别+形状，雷达给真实距离/TTC | 综合风险最准（用雷达距离/TTC 替换视觉估距） |
| **仅视觉** | 小目标/弱反射/出雷达视场的人或车 | 信视觉，用视觉接近度估距（现状逻辑） |
| **仅雷达** | **未知障碍物**（未训练类型，或被漏检的人/车） | 保留为「未知障碍物」，按 §5.3 计风险（几何主导） |

## 4. 雷达-视觉关联

雷达给**角度** `angle_deg`（−90~+90°，0=正前），视觉给**像素 bbox**。关联需把两者统一到同一坐标。

- **角度 ↔ 图像列**：用相机水平视场角 `FOV_h`（可配置，标定前默认值）把 bbox 水平中心换算成方位角，
  与雷达角度在容差内匹配；同方位多个目标时按距离最近匹配（LD2451 角分辨率粗，关联为「尽力而为」）。
- **分割路面门控（杠杆1）**：把雷达方位投影到**当帧已算好的道路分割掩码**上，判断该方位前方是否为路面。
  落在路面上 → 真·挡路；投影到路面外 → 路边杂波，压低。**复用已有分割结果，仅查表，几乎零延迟。**

> 关联是近似的（雷达 1D 方位 vs 视觉 2D 框），故仅用于「增强」与「门控」，不作为硬否决。

## 5. 综合风险公式（逐目标）

各因子均归一化到 [0,1]。沿用视觉单帧风险（[`visual_risk.py`](../../src/vision/risk/visual_risk.py)）的因子设计，雷达主要替换/增强「距离」维度。

### 5.1 视觉 ∩ 雷达（融合增强）
用雷达真实距离/TTC 取代视觉的粗略接近度：
$$R = \big[\,w_c\,c_{class} + w_k\,k_{kin}(TTC,d) + w_l\,l_{lateral} + w_d\,d_{drivable}\,\big]\cdot \phi_{conf}$$
其中运动学项
$$k_{kin} = 1-\frac{\min(TTC,\,TTC_{safe})}{TTC_{safe}} \quad(\text{接近时}),\qquad TTC=\frac{d}{v_{rel}}$$

### 5.2 仅视觉
退回纯视觉估计（bbox 底边接近度 + 尺寸），即现有 `calculate_detection_visual_risk` 逻辑。

### 5.3 仅雷达「未知障碍物」（A3：先验≈0，几何主导）
不知道是什么 → **不给类别先验**，风险全由几何/运动学决定：
$$R_{unknown} = f(d,\,TTC)\ \times\ g_{lateral}(\theta)\ \times\ \mathbb{1}[\text{在路面上}]\ \times\ \psi_{persist}$$
- $f(d,TTC)$：距离/TTC 风险（同 §5.1 的 $k_{kin}$，近且逼近→高）；
- $g_{lateral}(\theta)$：在途程度，方位越偏离行进走廊→越低；
- $\mathbb{1}[\text{在路面上}]$：分割路面门控（杠杆1）；
- $\psi_{persist}$：**持续可信度（杠杆3）**——单帧闪烁→低，连续多帧稳定跟踪→趋近 1，抗杂波。

### 5.4 场景级输出
取所有目标综合风险的最大值作为 `R_obs` 喂给现有 `risk_model`；未匹配的雷达未知障碍物若被
路面门控保留，则以 §5.3 结果一并参与 max，**保证视觉漏检的物理障碍不丢**。

**雷达只通过 R_obs 进入综合风险**：因雷达已在此融进 R_obs，`risk_model` 的独立距离项
`R_dist` 权重置 0（`risk_params.yaml`），其原权重并入 obs，避免雷达被**重复计算**。
> ✅ **视觉失效兜底（已实现）**：`fuse_vision_result(None/无掩码无框, radar)` 进入**纯雷达**模式，
> 仅输出"仅雷达未知障碍"的 R_obs（无图像也能算：运动学×横向角度×持续性，跳过路面门控保守保留）。
> `main_integrated` 中只要 `radar.valid` 即运行融合，故摄像头/模型失效时雷达仍经 R_obs 报警，
> R_dist=0 不丢安全冗余。

## 9. 雷达硬件规格（HLK-LD2451，来自官方手册）

| 规格 | 值 | 对融合的意义 |
|---|---|---|
| **水平探测角** | **±15°**（垂直 ±7°） | 雷达天然只看正前 30° 锥 → 路边大角度杂波被硬件排除；横向门控外边界用此值 |
| 探测距离 | 最远 100m，可配 10–100m | 远场可达；电动车近场为重，`dist_far_m` 默认 30 可调 |
| 扫描频率 | 100ms（有目标 10Hz；无目标 ~1Hz） | 融合按 ~10Hz 跑；持续性 3 帧≈0.3s 确认 |
| 距离/速度/角度 | 距离 0–100m(1m)、速度 0–120km/h、角度 1°（=上报值−0x80） | 关联容差可收紧到 6° |
| 输出协议 | 帧头 `F4F3F2F1` + 长度(LE) + 目标数 + 报警 + 目标×5B + 帧尾 `F8F7F6F5` | 解析见 `radar_reader.py`（已核对与协议一致） |
| 串口 | 115200, 8N1 | — |
| 可配置 | 检测方向(靠近/远离/均)、最小速度、灵敏度(触发次数+SNR阈值) | 建议方向设「均检测」或「靠近」，最小速度调低，利于近场未知障碍 |

> ⚠️ **安全关键待真机确认**：手册「速度方向」字段表9（01=靠近）与数据实例（00=靠近）**自相矛盾**；
> 现 `radar_reader.py` 按**实例**取 `00=靠近`（负相对速度）。上真机时务必用一个**已知逼近目标**确认，
> 取反会把接近当远离 → TTC 失效 → 漏报。

### 安装方向：本项目前装（手册场景为后装）

手册典型场景是**后向安装**（测后方来车/盲区），本项目把雷达装在**车前侧朝前**。区别如下：

- **不受影响**（纯物理，与安装无关）：距离、「靠近/远离」(=径向距离减小/增大)。前装时「车骑向前方障碍 → 距离减小 → 靠近」，
  TTC/接近逻辑照常成立——手册的后向场景只是举例，传感器测量本身一致。
- **受影响、需标定**：
  1. **角度左右符号**：`角度=上报值−0x80`，但「+角度=左还是右」取决于模组摆向。前装须确认 **雷达 +角度 = 相机画面右侧**；
     若镜像，置 `flip_radar_angle=True` 一键翻转（已在 `VisionRadarFusionConfig` 提供）。
  2. **±15° 宽轴必须水平**：保证那条 ±15° 的宽探测轴是左右方向（而非上下），否则成了竖扫。
- **检测方向配置建议**：前向避障下「靠近」(01) 恰好就是「我们正在逼近的前方障碍」，可用 01 或「均检测」(02) 留余量。
