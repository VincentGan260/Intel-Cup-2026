本系统的前向感知由两条并行的视觉链路与一路毫米波雷达构成。视觉链路在每帧上同时完成
**可通行路面语义分割**与**类别无关动态障碍物检测**，分别回答「前方哪里是能走的地面」
与「前方有没有挡路的障碍物」；雷达链路提供障碍物的**真实距离、相对速度与接近趋势**。
三者经**目标级融合**汇成统一的前向障碍风险 `R_obs`，输出给总风险模型驱动报警与电机响应。

与示例报告中健身操系统「云-边-端」的部署不同，本系统的所有感知与风险计算**全部在端侧
（DK-2500，Intel Core Ultra）实时完成**，无云端依赖——这是避障类安全系统对实时性与可用性的
硬性要求。整体实现框图如图 4.1。

```
            ┌────────────────────────────────────────────────────────┐
 摄像头 ───►│  可通行路面语义分割 (road-adas)  ──► road mask          │
            │  类别无关障碍物检测 (yolo26n-v2) ──► 检测框 + 置信度    │
            └───────────────┬────────────────────────────────────────┘
                            │  VisionResult
 LD2451 雷达 ──► RadarData ─┤
                            ▼
                视觉-雷达目标级融合 (§4.2)
                · 角度关联 + 分割路面门控
                · 逐目标综合风险 + 连续帧平滑
                            │  R_obs
                            ▼
                总风险模型 R = w₁·R_obs + w₃·R_pose + w₄·R_speed ──► 报警 / 电机
```

## 4.1 前向视觉感知模型实现

**选型总原则：先卡实时，再比精度。** 本系统是端侧（DK-2500）运行的避障类安全系统，对**延时**有
硬约束——分割、检测、融合、风险计算需在每帧内串行完成，整环必须维持实时（≥10FPS、单帧
≤100ms），否则「看到」滞后于「撞上」，再高的精度也失去意义。因此我们的选型不是「挑精度最高
的模型」，而是「**在满足实时延时的前提下，挑精度最好的轻量模型**」。这条原则直接决定了两路
视觉模型的初选：

- **分割初选 road-adas**：Intel OpenVINO 官方预置的轻量道路分割模型，编码-解码结构小、可直接
  在 Intel CPU/iGPU/NPU 上跑实时，且原生 IR 部署无需自行转换——是「够轻、能实时」的现成解；
- **检测初选 yolo26n**：YOLO 家族**最小的 nano 档**，参数量与算力需求最低、端侧推理最快，是
  在严苛延时预算下唯一能稳住实时的量级。

也就是说，road-adas 与 yolo26n 是先**用速度/延时把候选集卡到「能实时」**之后，再在其中按精度
取优、并通过后续对照评测（§4.1.1、§4.1.2）与驾驶域微调确认/补强的结果。下面分述两路实现。

### 4.1.1 可通行路面语义分割

**任务定义。** 我们把分割任务定义为**整片可通行路面（road）的逐像素提取**，而非汽车 ADAS
常用的车道级「可行驶区域（drivable area）」。原因在于载体是电动车：电动车不按机动车道行驶，
而是在路面、人行道边、混合交通中穿行，车道线语义对其意义有限；「整片路面」才是电动车真正
能骑的地面，语义上更贴合「前方能不能走」的风险判断，且 road 类在各公开数据集均有干净、明确
的标注，评测更公平。

**模型选型。** 采用 Intel OpenVINO Open Model Zoo 提供的 **`road-segmentation-adas-0001`**
（下称 road-adas）。该模型为轻量编码-解码结构，输入分辨率 512×896，逐像素输出
4 类（背景 / 路面 / 路沿 / 路面标识），我们取其中**路面（road）通道**作为可通行区域。
作为对照，我们另评测了实时分割网络 **PIDNet-S**[17]。

**后处理与可通行区域提取。** 模型输出的类别概率图经 `argmax` 得到逐像素类别，取 road 类
二值化为路面掩码 `road mask`。该掩码有两个下游用途：① 作为可通行区域先验参与障碍物风险计算
（障碍物落在路面上 → 真·挡路，落在路面外 → 压低，见 §4.2.1 的 `d_drivable` 因子）；
② 作为**雷达回波的路面门控**底图（§4.2.3）。为保证跨数据集可比，评测时用统一标签映射工具
`tools/unify_seg_labels.to_road_mask()` 把各集 GT 归一为 `{road=1, 背景=0, 忽略=255}` 再算 IoU。

**选型策略。** 我们在 road-adas 与实时分割网络 PIDNet-S[17] 之间做了对照评测（多数据集 +
ACDC 按天气分层），目的在**选型**而非陈列分数。选型逻辑是按电动车的真实出行条件取舍：
电动车常在夜间/雨雾出行，分割必须在**最难的条件下仍然可用**，因此评测刻意按天气/数据集分层、
不做掩盖短板的池化平均。结论是 road-adas 在恶劣天气、尤其**夜间**显著更稳（PIDNet 夜间近乎
崩塌、road-adas 仍可用），且更轻量；PIDNet 仅在其训练主场 Cityscapes 略占优。据此**分割选用
road-adas**——稳、轻、夜间强。具体 IoU 数字与按天气拆分见第六章系统测试。

### 4.1.2 动态障碍目标检测

**任务定义：类别无关。** 我们把检测任务定义为**「障碍物 vs 背景」的单类检测**（人 + 各类车
合并为一类 obstacle），而非区分人/车/卡车的精细多类检测。这并非简化省事，而是对电动车安全
场景的正确建模：

1. **风险不靠类别区分**：对电动车而言撞人与撞车的风险无法简单分高低，真正决定风险的是
   **几何**——距离、是否挡在路径上、目标大小，类别是次要因素；
2. **小模型分类本就不可靠**：nano 级模型 + 跨域（COCO→驾驶场景），精细分类脆弱，
   把决策建立在不可靠类别上会放大错误；
3. **规避类别编号对齐难题**：COCO/BDD/IDD 类别体系互不相同，按类评测需复杂易错的映射；
   统一成「障碍物」后两边先筛障碍物类、再不分类按 IoU 匹配，干净且鲁棒。

> 仍保留**「两轮车」关注子集**单独统计 recall——非机动车（电动车/自行车/摩托）是本项目最该
> 看见、最易漏检的对象，必须单独盯住漏检率。

**模型与微调。** 采用 Ultralytics **`yolo26n`**（nano 级，端侧实时）[15]，微调为**单类 obstacle**。
基线评测发现其短板根因是**域差**（COCO 通用域 ≠ 驾驶域），而非架构不行，故对症做法是**驾驶域
微调**而非换更大模型（换大模型会变慢、且仍是 COCO 域）。微调坚持两条工程纪律：

- **防数据泄漏**：测试用过的图绝不进训练（本地 BDD val 10000 张，测试 manifest 用掉一部分，
  剩余留出图才用于训练）；
- **两轮车缺口的发现与修正**：构建训练集时发现 883 张含两轮车的图**全部被测试集占用**，导致
  初版 v1 训练池两轮车为 0；遂将其**重切 600 训 / 283 测**并对两轮车图**过采样 ×3**，重训得 v2。

模型仍是 nano，**速度不变**；输出为单类的检测框 `(x1,y1,x2,y2)` + 置信度。

**评测设计（保证选型可信）。** baseline / v1 / v2 **同台**在同一 manifest 上重测确保可比；
IDD、DAWN 训练时一张未见，作为**纯泛化检验**——若在未训练过的域也变好，说明学到的是通用
特征而非死记某一数据集。这套设计保证「选 v2」的结论站得住，而非挑了个好看的测试集。

**结论与选型。** 微调以 recall 为先（漏检 = 安全命门），两轮车、夜间、小目标三大短板均明显
补齐，且未训练过的泛化域同步回升，故**检测选用微调版 v2**。需说明 yolo26n 仍是「precision 高、
recall 偏低」的保守型；对电动车安全而言**误报远没有漏检致命**，故后续再以雷达融合进一步补
recall（§4.2）。具体 mAP / recall / 两轮车 recall 数字与泛化对比见第六章系统测试。

### 4.1.3 基于 OpenVINO Runtime 的视觉模型端侧推理实现

两路视觉模型在端侧统一经 **Intel OpenVINO Runtime** 部署，推理链路如图 4.4。

```
 分割: road-adas  ─ OMZ 预置 IR ──────────────────────┐
                                                       ├─► OpenVINO IR (.xml/.bin)
 检测: yolo26n-v2  ─ PyTorch(best.pt) ─► ONNX ─► OV IR ─┘   FP32 / FP16 / INT8
                                                       │
                                                       ▼
                              OpenVINO Runtime ──► DK-2500 (CPU / iGPU / NPU)
```
**图 4.4 视觉模型端侧推理链路**

**模型转换。** road-adas 直接采用 Open Model Zoo 预置的 OpenVINO IR；微调后的 yolo26n-v2
经 Ultralytics 导出为 OpenVINO IR（`export_finetuned.py`，一并产出 FP32 与 FP16）。我们先在
**FP32** 上抽查确认 **PyTorch ↔ OpenVINO 导出数值一致**，从而把「模型本身准不准」与「在板子上
快不快」彻底解耦——精度只需在 FP32 上评一次即代表模型能力。

**精度档位。** FP32 为精度基线；FP16 精度等同 FP32、体积约为一半（yolo26n-v2 FP32 9.6MB →
FP16 4.8MB），用于端侧 iGPU；INT8 量化的精度损失留待量化轮专门权衡。已部署模型见表 4.1。

**表 4.1 端侧部署模型**

| 用途 | 路径 | 备注 |
|---|---|---|
| 检测 FP32（管线默认） | `models/yolo26n_v2_openvino_model/` | `detection.yaml` 已指向此 |

## 4.2 视觉—雷达协同的前向障碍风险表征实现

视觉链路知道「是什么、什么形状、哪里是路面」，但**单目估距粗、且有漏检**；毫米波雷达
LD2451 知道「多远、多快、在不在接近」，但**不知道是什么、有路边杂波**。二者盲区互补——
这正是融合的根本动机。本节实现一个**目标级**融合模块
（[`src/fusion/vision_radar_fusion.py`](../../src/fusion/vision_radar_fusion.py)），按角度把雷达目标与
视觉框关联，逐目标算出综合风险，时序平滑后输出场景级 `R_obs`。该模块**模型无关、零额外推理**
——只在「已算好的检测框 + 分割掩码」上做纯算术与查表，满足端侧实时约束。

### 4.2.1 视觉风险特征提取

对每个检测框，从视觉信息提取四类归一化到 `[0,1]` 的风险因子（实现见
[`visual_risk.py`](../../src/vision/risk/visual_risk.py)），合成单帧视觉风险：

$$R_{vision} = \big[\,w_c\,c_{class} + w_k\,k_{kin} + w_l\,l_{lateral} + w_d\,d_{drivable}\,\big]\cdot \phi_{conf}$$

| 因子 | 含义 | 提取方式 |
|---|---|---|
| $c_{class}$ 类别先验 | 目标类别带来的基础危险度 | 类别无关检测下统一基线，主要由几何主导 |
| $k_{kin}$ 接近度 | 目标有多近/逼近多快 | **仅视觉时**用 bbox 底边纵向位置 + 尺度粗估；有雷达时由 §4.2.2 替换 |
| $l_{lateral}$ 在途度 | 是否挡在行进路径上 | 由 bbox 水平方位相对行进走廊的偏离计算 |
| $d_{drivable}$ 路面重叠 | 目标是否落在可通行路面上 | **复用 §4.1.1 的 road mask**，算检测框与路面掩码的重叠比例 |
| $\phi_{conf}$ 置信度调制 | 检测越可信，风险越实 | 由检测置信度映射 |

这一套因子对**仅视觉**目标（小目标/弱反射/出雷达视场的人车）即为最终风险；对**视觉∩雷达**
目标，其中的接近度 $k_{kin}$ 会被雷达的真实距离/TTC 取代（§4.2.3）。

### 4.2.2 雷达距离与相对运动特征引入

LD2451 每个扫描帧给出若干目标，每目标含**方位角、距离 $d$、相对速度 $v_{rel}$、接近/远离标志**，
另有帧级报警位。我们由此构造**运动学风险**，把视觉最缺的「多远、多快」补上：

$$TTC = \frac{d}{v_{rel}}\ (\text{接近时}),\qquad
k_{kin} = 1 - \frac{\min(TTC,\,TTC_{safe})}{TTC_{safe}}$$

TTC（碰撞时间）越小、距离越近，风险越高；$TTC \ge TTC_{safe}$（默认 5s）时风险≈0。这里距离与
相对速度是**联合**使用的；当目标**远离或静止**（相对速度不再指示前向威胁）时，TTC 失去意义，
$k_{kin}$ 退回**纯距离风险**（越近越高）作保守兜底——即"逼近看 TTC、不逼近只看多近"。该 TTC 风险
形式源于交通安全领域经典的碰撞时间度量[7]，安全距离阈值的标定可参照 RSS 安全纵向距离模型[8]。
雷达硬件规格如表 4.2，其参数直接约束了融合的关联容差与门控边界。

**表 4.2 HLK-LD2451 关键规格及对融合的意义**

| 规格 | 值 | 对融合的意义 |
|---|---|---|
| 水平探测角 | **±15°**（垂直 ±7°） | 天然只看正前 30° 锥 → **路边大角度杂波被硬件排除**，横向门控外边界取此值 |
| 探测距离 | 最远 100m，可配 10–100m | 远场可达；电动车近场为重，`dist_far_m` 默认 30 |
| 扫描频率 | 100ms（有目标 10Hz） | 融合按 ~10Hz 跑；持续性 3 帧 ≈ 0.3s 确认 |
| 距离/速度/角度 | 1m / 0–120km/h / 1°（=上报值−0x80） | 关联容差可收紧到 6° |
| 串口 | 115200, 8N1 | 解析见 `radar_reader.py`（已核对协议一致） |

> ⚠️ **安全关键待真机标定**：手册「速度方向」字段表 9（01=靠近）与数据实例（00=靠近）**自相矛盾**，
> 现按实例取 `00=靠近`（负相对速度）。上真机时须用一个**已知逼近目标**确认，取反会把接近当远离
> → TTC 失效 → 漏报。

### 4.2.3 视觉—雷达关联与 R_obs 构建（三类目标 / 未知障碍 / 雷达兜底）

**坐标关联。** 雷达给 1D 方位角、视觉给 2D 像素框，需统一到同一坐标：用相机水平视场角 `FOV_h`
把 bbox 水平中心换算为方位角，与雷达角度在容差 `assoc_angle_tol_deg`（默认 6°）内匹配；同方位
多目标按距离最近匹配。因雷达角分辨率粗，关联仅用于「增强」与「门控」，**不作硬否决**。

**三类目标分别处理**（这是融合的核心，体现「并集保 recall + 几何门控保 precision」）：

| 情形 | 处理 | 风险来源 |
|---|---|---|
| **视觉 ∩ 雷达** | 置信最高：视觉给类别/形状，雷达给真实距离/TTC | $k_{kin}$ 用雷达 TTC（§4.2.2）替换视觉估距，最准 |
| **仅视觉** | 小目标/弱反射/出雷达视场的人车 | 退回纯视觉风险（§4.2.1） |
| **仅雷达** | **未知障碍物**：未训练类型（杆/栏/落物）或被漏检的人车 | 几何主导（见下式），**不丢弃** |

**仅雷达「未知障碍物」**不给类别先验，风险全由几何/运动学决定：

$$R_{unknown} = f(d,\,TTC)\ \times\ g_{lateral}(\theta)\ \times\ \mathbb{1}[\text{在路面上}]\ \times\ \psi_{persist}$$

- $f(d,TTC)$：距离/TTC 风险（近且逼近 → 高）；
- $g_{lateral}(\theta)$：在途程度，方位越偏离行进走廊 → 越低；
- $\mathbb{1}[\text{在路面上}]$：**分割路面门控**——把雷达方位投影到 §4.1.1 的 road mask 上查表，
  落在路面 → 真·挡路，投影到路面外（护栏/路沿）→ 滤除。复用已算掩码，几乎零延迟；
- $\psi_{persist}$：持续可信度（§4.2.4）。

> **理论依据：证据栅格的「未知」态。** 雷达看到、视觉没识别的目标之所以**保留而非丢弃**，
> 是因为它可能是没训练过的障碍或被漏检的人车。证据占据栅格（Dempster-Shafer）把单元状态分为
> **Free / Occupied / Unknown** 三态，「Occupied 但 Unknown」恰是「有东西、但不知道是什么」[10]。
> 这把「不知道」建模为**独立状态**，正是保留未知障碍物的理论支撑——守住「漏检最致命」的安全命门。

**场景级 R_obs。** 取所有目标综合风险的最大值作为 `R_obs`，未匹配但通过路面门控的雷达未知障碍
一并参与 max，保证视觉漏检的物理障碍不丢：

$$R_{obs} = \max_{i \in \text{所有目标}} R_i$$

**避免重复计算 + 视觉失效兜底。** 雷达已在此折进 `R_obs`，故总风险模型中**独立的雷达距离项
`R_dist` 权重置 0**（`risk_params.yaml`），其原权重并入 obs，避免雷达被重复计算：

$$R = w_1\,R_{obs} + w_3\,R_{pose} + w_4\,R_{speed}\qquad(w_2 = 0)$$

同时保留**视觉失效兜底**：当摄像头/模型失效（无掩码无框）时，融合进入**纯雷达模式**，仅输出
「仅雷达未知障碍」的 `R_obs`（运动学 × 横向角度 × 持续性，保守保留），故 `R_dist=0` 不丢安全
冗余——这是一项安全侧的有意冗余设计。

### 4.2.4 连续帧平滑与风险等级输出

单帧雷达/检测都会抖动（杂波、闪检），直接报警会误震或漏稳定威胁，故引入**时间持续性**作为
平滑机制（杠杆3）。模块维护轻量目标轨迹，按方位关联，计算持续可信度：

$$\psi_{persist} = \min\!\Big(1,\ \frac{\text{连续命中帧数}}{N_{persist}}\Big),\quad N_{persist}=3\ (\approx 0.3\text{s})$$

单帧闪烁 → $\psi$ 低、被压制；连续多帧稳定跟踪 → $\psi \to 1$、风险如实上升。连续丢失
`track_max_misses`（默认 3）帧后删除轨迹。$\psi_{persist}$ 既作为未知障碍风险的乘子（§4.2.3），
也整体抑制场景级 `R_obs` 的逐帧抖动。

**风险等级输出。** 平滑后的 `R_obs` 送入总风险模型得综合风险 `R`，再离散化为风险等级（低/中/高）
驱动报警与电机。为避免等级在阈值附近频繁跳变，等级判定带**迟滞**（升档与降档用不同阈值）。
逐帧的 `risk_obs / risk_total / risk_level / radar_nearest_m / radar_min_ttc / vision_max_risk`
均写入 CSV 日志，可直接画风险-时间曲线用于第六章的效果评估。

> 临界触发中→高风险），以及未知障碍兜底与持续性平滑的效果。*（占位，用实测/回放数据出图）*

## 本章小结

本章实现了电动车前向感知的完整视觉-雷达风险链路：视觉端用**类别无关 + 整片路面**的正确任务
简化，配合**驾驶域微调**（不牺牲速度）补齐 nano 模型的小目标/夜间/两轮车短板；雷达端补上视觉
最缺的真实距离/TTC；二者经**目标级融合**——并集保 recall、几何门控保 precision、未知障碍不丢、
视觉失效雷达兜底——汇成统一的 `R_obs`，时序平滑后输出风险等级。整条链路端侧零额外推理，
为后续的端侧优化（第五章）与效果实测（第六章）奠定基础。
